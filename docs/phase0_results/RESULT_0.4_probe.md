# RESULT 0.4：骨干逐层线性探针（2026-10-20）

> 按协议，这一步只用于选骨干，不作为论文主张。

## 设置

- **代码**：`scripts/phase0/probe_backbones.py`（自包含）；Modal 封装 `probe_modal.py`。
- **smoke**：先在 Kaggle（`jiunige`，T4）上跑通。
  - 第 1 版失败，原因是 Kaggle 预装的 transformers 5.x 与 NTv2、GENERanno 的远程代码不兼容。
  - 第 2 版把 transformers 固定为 4.57.6 后跑通。
- **正式运行**：Modal A10G，4 个骨干并行，各 1.5–6 分钟。
- **数据**：
  - 在 hg38 chr21 上训练（300 个 6 kb 窗口，一半以 lncRNA 外显子为中心，一半随机），在 chr20 上评测（300 个窗口，共 30 万个位点）。
  - 标签来自 GENCODE v50，不分链。
  - 所有模型都在每 6 bp 的中心位置取样，因此样本量相同。
- **探针**：每层一个线性层，正类加权 BCE，2 个 epoch。
- **输出**：Baobab `outputs/PHASE0/0.4_probe/full/`；本地副本在 `results/0.4_probe/`。

## 解读

1. **选定骨干：GENERanno-1.2b-cds**。它与 coding 项目（M28）和 Carbon-A 用的是同一支权重。
   - 协议里的假设是"CDS 监督可能压制非编码信号"，结果是**被推翻**：这支权重在 lncRNA 外显子和剪接位点上反而最强。最可能的解释是，CDS 监督学到的是通用的外显子和剪接特征，这些特征对非编码外显子同样有用。
   - 这让"编码 ⊗ lncRNA 乘积语法共享同一个骨干"在工程上变得最简单。
2. **lncRNA 外显子的序列信号本身较弱**。
   - 最好的骨干，lnc 外显子 AUPRC 是先验的 2.4 倍，mRNA 外显子约 9 倍。
   - TSS 和 TES 在所有骨干上都很弱，AUPRC 只有先验的 5–6 倍，绝对值 < 0.09。
   - 因此单靠逐碱基分类不够，必须靠语法与结构约束，以及正确处理"未注释并不等于阴性"的训练目标，也就是 0.5 要检验的内容。这也解释了为什么端到端方法在 lncRNA 上几乎都是 0。
3. **对 Caduceus 的观察**：GENATATOR 的底座在冻结特征上最弱。不过 GENATATOR 是整模型微调的，所以这一条不能用来解释它的表现。
4. **局限**：
   - 线性探针、单次运行，窗口抽样是确定性的（seed 0）。
   - 标签不分链；重叠的 isoform 简化处理为外显子优先。
   - 骨干之间的差距（0.38 对 0.25）大于这里可见的噪声，但没有做置信区间。
   - 作为选骨干依据足够；如果要写进论文，需要补 seed 和置信区间。
