## 本轮新发现的问题：HiGHS 预处理误报不可行

第一次完整运行有 5 处 B4 不一致，方法判「可定量区分」，oracle 判「信息受限」。逐一核查：
- **oracle 是对的**。seed 329 只有一个起点、一个终点，所有转录本的端点观测必然相同。
- **方法的混合整数规划把一个可行模型报成了不可行**。存在约束违反为 0 的可行点；关掉 HiGHS 预处理（presolve）就能解出来。

修法：方法中每次「不可行」都关掉预处理再解一次确认；复核解出可行解时就采用它，之后仍做丰度重算和直接检查。
- 本轮共复核 18,538 次「不可行」，其中 5 次被推翻，都出现在信息受限的双份模型里。
- 三态判定这一轮没有被推翻的情况，但同一复核也加在三态判定上。

这说明「求解器返回不可行」确实不能直接当证书。真实数据上也要保留这道复核，并报告被推翻的次数。

## 注明

1. **信息受限 oracle 有 90 次跳过**（0.8%）：含 / 不含目标的支持集对数超过 3,000，穷举太慢。跳过的不计为通过。
   - 补算（ChatGPT 第 7 轮指出原句与代码不符，已更正）：90 次全部来自 3 个 12 条候选路径的实例（seed 65、271、579），全部在 δ = 1。
   - 方法判为「信息受限」73 次：ends 25、short2 25、link 23。这些各有一对可直接复核的见证解，见证检查全部通过。
   - 判为「可定量区分」17 次，全部是 pe。这是没有独立证明的阴性判定。
   - 正确口径：所有完成的独立 oracle 检验都一致，不是所有类型判定都经过独立验证。
2. **「期望观测相同」按同一丰度尺度比较**。即假定新测序能校准到现有定量的尺度（同一文库或加标准品）。只能比较比例的情形是双线性问题，未处理。
