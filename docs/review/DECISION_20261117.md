## 1. 决定

**不投现稿（选 C），但不把它当垃圾扔掉。**
- 现稿冻结归档：全稿、图和全部预注册结果原样保留。
- 无论后面走哪条路，它都是新工作的诊断部分：基准、检出与界定的差距、端点分解。
- 不再为它加 seed、物种或润色。

**理由**（两方独立得出，结论一致）：
1. **方法没有解决核心任务**：S50 约 7%，lncRNA 结构为 0，编码结构靠 Tiberius。按现有结果，最可能被接收的是 Bioinformatics / NARGAB 一档，达不到目标。
   - 我原先估计 Genome Biol / Genome Res 一档 50–60%、Nat Commun 20–30%，现在看偏乐观，下调到 Genome Biol 约 10–20%、Nat Commun 约 5%。
2. **「端点限速」还缺两个关键对照**：
   - 一是简单特征（CpG）的检出对照：检出靠 CpG，这一点是我们自己的结果；
   - 二是最强的长上下文模型（AlphaGenome 的起始轨道）的端点测试。
   - 另外还有一项可信度风险：GENERanno-cds 的训练数据没有公开。
   - 带着这三个缺口投稿，审稿人一定会问到，而且每一个都可能改写结论。
3. **现在发表会把真正的问题提前消耗掉**：DNA 能确定什么，什么需要细胞状态或实验信息，少量哪种证据能把「区域」变成「转录单位」。后续工作要用同一套评测和诊断，会被看成增量。
4. **竞争**：GENATATORs、AlphaGenome 类模型和 SpliceAI2 都在逼近，但都还没占住这个问题。所以没必要为抢先而发弱版，也不能无限期拖下去。为此设定四周的里程碑和明确的放弃条件。

### 第 2–4 周：三条件实验（方向 2，「稀疏端点证据能否把区域变成转录单位」）

- **数据**：LRGASP WTC11。ssCAGE 和 QuantSeq 作为输入证据，独立的 PacBio 重复作为验证；不再以 GENCODE canonical 为真值。下载前先核实各数据编号，并问作者。
- **三个条件**：只有 DNA / oracle 端点 / 真实稀疏证据，并做证据量梯度（例如 10%、30%、100% 的峰）。
- **对照分两种信息预算**：
  - 只给端点：吸附到最近峰、AUGUSTUS hints；
  - 给完整转录组：StringTie / IsoQuant。
- **测试区域**：先在 chr18 上开发，然后在 chr12 上一次性读取。
  - 严格还是低成本方案，在写计划时决定：严格方案要重训排除 chr12 的轻量头，3 个 seed 约 8–12 GPU 小时；v2.0 每个 seed 训练约 2.4 小时，另外还要提取替换窗口的特征；低成本方案只评估不与训练窗口重叠的区域。
  - 冻结前要先确认 chr12 上可验证的 lncRNA 数量足够。
- **第一阶段门槛**：S50 召回 ≥ 0.30、精度 ≥ 0.40，并在同等证据下优于吸附基线；同时报告有证据子集占全部 lncRNA 的比例。结构（L2 ≥ 0.10–0.15）放到下一阶段。

### 方向 2 的额外风险（Claude 补充，ChatGPT 未提）

- 新测序的基因组（EBP / DToL）越来越多带有混合组织的 Iso-Seq。有长读长的地方，IsoQuant / StringTie 就能做 lncRNA；所以我们的用武之地必须是**读段覆盖不到的 lncRNA**（低表达、组织特异），或者**只有便宜的端点测序、没有长读长的场景**。
- M1 的结果报告必须回答：在真实的证据预算下，有多少 lncRNA 是只靠证据驱动的工具拿不到、而「序列先验 + 稀疏证据」能拿到的？这个比例太小，方向 2 就没有用户。
