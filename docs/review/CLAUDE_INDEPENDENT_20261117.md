# Claude 的独立判断（2026-11-17，在读 ChatGPT 回答之前写定）

> 目的：先把自己的判断写下来，再读外部意见，避免被它带偏。之后的对照与决定见 `DECISION_20261117.md`。

## 1. 现状能发在哪里

- **Genome Biology / NAR / Genome Research 一档**：大约 50–60%。
  - 理由：三部分都扎实，而且全程预注册。
    - 基准：真值在快速增长，现有工具约 3%。
    - 检出：约 10 倍于 GENATATOR，跨物种可迁移。
    - 端点诊断：在 chr20 上复现，且两个专用模型也失败。
  - 弱点：方法本身没有解决问题。
- **Nat Commun**：20–30%。需要编辑认可「限速步骤」这个分析性结论的价值。
- **Nat Methods**：低于 10%。方法没有把 lncRNA 注释做出来：S50 只有 7%，结构为 0。

**最致命的批评**：
1. **检出的 30% 可能只是「CpG 岛 + 长基因」探测器。**
   - 依据：第 11 节自己说明了检出靠 CpG 和跨度。
   - 缺口：只用 CpG/GC/序列组成的简单检测器对照还没做（RESULT_B1 写明「未做」），审稿人一定会要。如果简单检测器能达到 20% 以上，方法贡献就基本塌了。
2. **「序列模型定位不了 lncRNA 端点」没有对最强模型做测试。**
   - AlphaGenome（1 Mb 上下文）有逐碱基的 CAGE / PRO-cap 输出，而且分细胞类型。
   - 我们只测了它的 RNA-seq 分段（用于检出），没测它的起始轨道（用于定位端点）。
   - 审稿人会说：Puffin 只有局部上下文，GENERanno 是冻结的，这个结论在 2026 年说服不了人。
3. **「端点是限速步骤」在生物学上不算意外。**
   - lncRNA 起点多来自增强子（Hon 2017），表达细胞类型特异，5′/3′ 端注释不全，这些早已为人所知。
   - 我们的新意在于端到端量化和容忍度测量，属于「有用但不惊艳」。

## 2. 现在发会不会浪费好想法

- **有价值的核心想法**：给成千上万个新测序的基因组（EBP / DToL）自动出 lncRNA 注释。这个需求真实存在，而且没人能做。
- 但我们的结果本身就在说：只靠序列，做不到界定。所以「纯 ab initio lncRNA 基因注释器」这个大想法可能本来就没法完整实现。
  - 现在发表「检出 ≠ 界定、端点限速」，消耗的不是一个能做成的大工作，而是在给这个问题划边界。
  - 后续工作（细胞类型条件化的端点模型、只要少量证据的注释器）反而可以引用它作为动机。
- **反方最强的论点**：一旦把「端点不可预测」写成结论发表，如果后续自己证明「换个条件（细胞类型）就可预测」，前一篇就成了被自己推翻的弱结论；而且一个想法通常只有一次被顶刊接收的机会。
  - 我的看法：这个风险真实存在，而且正好可以用下面第 3 节的实验 1 先排除。
- **被抢先的风险**：
  - GENATATORs 在做区间内分割，方向是结构，不是端点。
  - AlphaGenome 类模型可能被别人直接拿来做 lncRNA 起点注释，这是最大的风险。
  - SpliceAI2 做的是剪接和已知基因的重建，与端点关系较远。

## 3. 如果继续：按决定性排序

1. **AlphaGenome 的起始 / 终止轨道定位 lncRNA 端点（决定性，约 3–5 Colab CU，0 训练）**
   - 假设：低 CpG lncRNA 的起点，从序列上看并非不可定位，而是细胞类型特异的。
   - 读数：
     - Loc1k，分两种取法：所有细胞类型 CAGE / PRO-cap 轨道取最大值，以及取均值；
     - 按 CpG 四分位分层；
     - 用 RNA-seq 覆盖度的下降点定位终点。
   - 结果解读：
     - **成功**（低 CpG 起点显著高于随机，而且「取最大值」优于「取均值」）：主线升级为「lncRNA 端点由细胞类型编码；ab initio 注释需要以细胞类型为条件的模型」，可以接着做条件化注释器，这是更大的工作。
     - **失败**：「当前序列模型定位不了」的结论扩展到最强模型，稿件明显变硬，可以直接投。
   - 限定：AlphaGenome 的 all_folds 是样本内的；条款不允许用它的输出训练我们的方法，只能作对照。
2. **简单特征的检出对照（0 GPU）**
   - 做法：在 chr18 上开发 CpG 岛 / GC / 序列组成的位点检测器，到 chr20 / chr9 一次性读取，同一把尺子（L1 和 S50）。
   - 结果解读：
     - 简单检测器比我们低得多：方法贡献成立。
     - 接近我们：必须如实改写成「检出主要靠启动子类型」，方法学主张基本撤回。
   - 无论结果如何，投稿前都必须做。
3. **少量证据的 lncRNA 注释（更大的方法工作，几周）**
   - 做法：解码器把一个组织的 CAGE / Iso-Seq 端点当作位置 bonus 输入（不用重训，语法本来就支持）。
   - 读数：S50 从 7% 能升到多少（参照：GENCODE v41 是 40%），对比 StringTie / IsoQuant 在同样少量数据下的表现。
   - 这是「可用工具」那条路，适合 Nat Methods 方向，但与证据驱动的成熟流程竞争激烈，风险高。

## 4. 我的初步建议

**(B) 先补两个决定性的小实验，再决定投稿还是升级为大计划。**
- 两个实验是第 3 节的 1 和 2，都不需要训练，合计约一周、几个 CU。
- 门槛：
  - 实验 1 成功（低 CpG 起点在「各细胞类型取最大值」时 Loc1k ≥ 0.25，且比取均值高 ≥ 1.5 倍）→ 不投现稿，转为「细胞类型条件化端点」的大计划，现有结果作为其中的诊断部分。
  - 实验 1 失败，且实验 2 中简单检测器的 L1 不到我们的一半 → 按现稿（加这两项）投 Nat Commun / Genome Biol。
  - 实验 2 中简单检测器接近我们 → 撤下方法学主张，改投 Genome Res / Genome Biol 的分析类文章，或者转向实验 3。
