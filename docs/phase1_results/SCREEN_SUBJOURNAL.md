## 结论（先看这里）

- **现状定位**：
  - 位点层面强：chr20 lnc L1 Sn 0.306、严格 Pr 0.422，约为 GENATATOR 的 11 倍。零样本到鸡和斑马鱼约 0.32–0.35。新位点 59% 有转录证据，对照为 29%。
  - 结构层面空白：lnc 内含子链 L2 = 0。剪接势能、自训剪接网络、外部编码证据三条改进在 chr18 上都未达有效。
  - 按现有结果，预计只够 NAR / Genome Biol 量级。子刊需要的是**新的结论**，不是把同样的数字再推高一点。
- **推荐主线：「在哪里」与「怎么剪接」的分离**。
  - 核心论点：DNA 序列能告诉我们 lncRNA 基因在哪里，却定不了它的外显子–内含子结构。原因是 lnc 结构由低使用量的剪接决定，而现有序列模型都预测不了低使用量剪接。
  - 我们已有的负结果（L2 = 0、剪接 AP 0.14–0.16、真值上限 0.071），可以由此升级为一条可量化、有对照、跨模型的规律。
  - 查新结论：lnc 剪接效率低的生物学已有报道（Mele 2017、Krchňáková 2019）。但没找到跨模型、按使用量匹配的预测上限研究，也没找到把它与基因结构解码连起来的工作。属「部分新颖」，新的部分正是我们能做的。
- **必须先补的两个风险点**：
  1. **SpliceAI 在 lncRNA 上的高分**。据查新报告，NAR 2026 的复评给出 SpliceAI 在其 lncRNA 集上 auPRC 0.963，与我们的 AP 0.14 冲突。很可能是口径不同：他们的负例是转录本内全部位置，我们的是满足基序的位置，而且我们的真值含 v47 起大批 CLS 新增内含子。必须在同一批位点上把两种口径都算出来，否则审稿人会直接拿这个反驳。
  2. **AlphaGenome**（Nature 2026）。它从序列预测剪接位点和连接，训练标签来自 GTEx / ENCODE 的 RNA-seq，包括 lnc 的剪接。它是必须比较的对照：可能在 lnc 位点检出上比我们强（威胁 C3），也可能在 lnc 剪接位点上比 SpliceAI 强得多。后一种情况下，把它的剪接预测接进我们的语法解码器，推理时仍只用序列，有可能解开结构问题。这是现在唯一看得到的结构突破口。
- **推荐顺序**：
  - 第 1 批不需要任何下载，CPU 为主，约 1 周。
  - 第 2 批需要下载，走决定卡，约 1–2 周。
  - v2.0（校准 + chr9）放到第 1、2 批之后，再按新结果重写草案后冻结。如果 AlphaGenome 剪接有用，它会成为 v2.0 的主体，而不是只有校准。
  - 11-30 不再是期限。

**不推荐**：
- 再训新的剪接网络。两次已证明只看序列的剪接网络区分不了。
- G2 候选格。约 12 T4 小时 / seed，召回门过了但可达性只有 65%。
- 把编码潜能作为头部输入重训。Vipsania 诊断已表明外部编码证据增益接近 0。

## 3. 推荐组合与顺序

**第 1 批（现在就能做，不下载，约 1 周）**：
1. **S1 核心**：
   - 在 chr20 上用 Snaptron gtexv2 的连接定义位点，与 GENCODE 无关，避免查新提醒的循环论证：CLS 新增内含子本来就要求 recount 支持。
   - 正例为观察到剪接的位点，按使用量（读段数、样本数）分层；负例为满足基序、在 1.9 万个样本里从未被剪接的位置。
   - 类别按所在位点（lnc / mRNA / 基因间）分，再按注释年代分（v41 已有 / v47 起新增）。
   - 模型：SpliceAI、自训 S10k、Vipsania（对照）。每个都同时报两种口径：基序候选 AP，以及 SpliceAI 论文式的转录本内 top-k / auPRC，用来和文献对上。
   - 读数和判读规则先写进 `PLAN_S1.md` 并提交，再算。
2. **S3 前半**：位点检出与启动子、U1–PAS、重复序列的相关分析，只用 CPU 和已有数据。
3. **GENATATORs 附录核对**（案头）：确认它有没有报 lnc 内含子链精度，以及「首个」能不能说。
4. **预测封存**：把 v1.9 三个主模型在 chr18 / chr20 / T2T / 面板物种上的全部预测算 sha256，打时间戳提交，为以后的前瞻检验留底（S6 只做到这一步）。

**第 2 批（要下载，走决定卡，约 1–2 周）**：
- S2 AlphaGenome（先查硬件要求和许可，再决定在 ont 还是 Modal 上跑）。
- S1 扩展：Pangolin / SpliceTransformer 权重；可选 chr18 Snaptron 查询，让开发染色体也有使用量。
- S5 小鼠零样本；S4 同线性链文件。

**第 3 批**：S7 v2.0。按第 1、2 批的结果重写 DRAFT_V20（若 S2 ③ 有效，加入 AlphaGenome 剪接势能），再走冻结卡，chr9 只读一次。S8、S9 视主线需要安排。

**这条线可能的论文骨架**（Nat Commun / Genome Res 级，S2 ③ 成功则可冲 Nat Methods）：
1. 现有注释器看不见 lncRNA（基准，已有）；
2. 结构化语法解码从序列找到 lnc 位点：chr20、chr9、小鼠、零样本物种，转录证据和同线性两种独立验证；
3. 但结构从序列定不下来：跨模型上限、使用量和注释年代分解、真值上限连到解码；
4. 位点靠什么被找到（S3）；
5. 含义：lnc 注释应当「序列定位点 + 少量转录证据定结构」。若 AlphaGenome 剪接势能有效，则改写为「RNA-seq 训练的序列模型补上了结构」。

## 5. 风险与负结果的写法

- S1 若显示差距完全由使用量解释，结论就写成「lnc 结构难，是因为 lnc 剪接整体低使用」。这是对 lnc 注释策略有用的定量结论，仍然成立。
- S2 若 AlphaGenome 的位点检出比我们强，就把它写进主表，诚实报告，并把我们的贡献收窄到「端到端的基因结构语法与 GFF3 输出、零样本物种」。AlphaGenome 只给轨道，不给基因模型。这一点必须在第 2 批尽早查清。
- 每项分析先写判据，结果无论正负都写进结果文档和看板。
