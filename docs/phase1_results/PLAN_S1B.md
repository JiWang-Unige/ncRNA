# S1b 计划：lnc 结构失败的分解，边界 vs 剪接（定稿，2026-11-04）

> 状态：**已冻结（2026-11-04）**。用户在决定卡 `subjournal-portfolio` 上选了第一项（「按照推荐来」）。本文件在任何 S1b 数字算出之前提交。与 11-04 草案（302bed9）相比只改了实现方式和资源两处，都是在读数之前改的，见 §2、§5。
> 只用 chr18（开发染色体）和已有的 v1.9 后验，不训练。chr9 不碰，chr20 不用。

## 1. 问题

GENATATORs 在已知转录本区间内能定出 25.6% 的 lnc 外显子结构（T2T chr20，RefSeq），而 v1.9 端到端的 lnc L2 为 0。L3.diag 已经看到两个现象：预测跨度是真值的 2.77 倍；TSS / TES 偏差中位约 10 / 17 kb。SPLICE_DIAG 的真值剪接上限是 L2 0.071（seed 42）。

问题是：结构失败主要来自位点边界，还是来自剪接位点？

## 2. 设定

三个主模型（g1b-42 / 123 / 456-ke，权重平均），chr18，MEAX γ = 3，τ 按 v1.9 §16。和 v1.9 唯一的差别是下面的约束：

| 设定 | 约束 | 说明 |
|---|---|---|
| A0 | 无 | v1.9 原样，应逐字节复现已有结果 |
| A1 真值边界 | lnc 态只允许出现在 v50 lnc 基因的真值区间内（同链，从最外 TSS 到最外 TES） | 等价于「位点和边界都已知」，最接近 GENATATORs 的设定 |
| A2 真值剪接 | 沿用 SPLICE_DIAG 真值上限的剪接势能 | 三个 seed 都跑；已有的 seed 42 结果作复现核对 |
| A3 两者都给 | A1 + A2 | 结构的上限 |

- A1 的实现（定稿）：把 NEG（−1e5）加在真值区间外该链 lnc 四个状态（E / L / I / R）的发射上，再做精确前向–后向。得到的就是「已知 lnc 基因边界」条件下的后验。mRNA 态与基因间态不动。
  - 代码：`splice_diag.py --span-oracle`。草案里写的「后验置零再归一化」只是近似，不再使用。
  - 单元测试 `tests/test_span_oracle.py` 已在 ont 上通过（2 项）：区间边界正确；区间外 lnc 后验 < 1e-12；区间内保留质量。
- A2 / A3 的真值剪接与 SPLICE_DIAG 相同：`--oracle --w 1`。
- 复现核对：
  - A0 用改过的脚本、w = 0 重跑 seed 42，后验 sha256 必须与 P1.5 chr18 读取一致。
  - A2 seed 42 的 genes.json 必须与 SPLICE_DIAG 的 `g1b-42-ke_oracle` 一致。
  - 任一不一致就停下查原因，不往下读。
- 每个设定只解码一次，不调 γ / τ。

## 3. 读数（写定）

- 每个设定、每个 seed：lnc L2 内含子链 Sn / Pr、L3 剪接点 P / R、L1 Sn / 严格 Pr、外显子覆盖中位数、TSS / TES 偏差中位数。尺子与 P1.5 相同。
- 主读数：三 seed 平均 lnc L2 Sn。
- 外显子覆盖中位数和 TSS / TES 偏差中位数用 `diag_l2.analyse`（与 L3.diag 同一函数），算在 τ 过滤后的最终 lnc 预测上。

## 4. 判据（写定）

- **「边界是主要瓶颈」**：A1 的三 seed 平均 L2 Sn ≥ 0.05，且高于 A2。→ 进 S11（两阶段解码），并把它作为 v2.0 的候选主体。
- **「剪接是主要瓶颈」**：A2 高于 A1，且 A1 < 0.05。→ 不做 S11；结构部分按 S1 的结论写。
- **「两者都要」**：A1、A2 都 < 0.05，而 A3 ≥ 0.05。→ 写成分解结果；S11 只在加上边界细化后再议。
- **都不行**：A3 也 < 0.05。→ 结构问题不在边界和剪接位点本身，而在外显子组合（内部外显子的取舍），如实报告。
