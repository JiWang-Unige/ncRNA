## 结论

**按事前规则，落在最低一档：只能说「转录相关区域的检出」，「lncRNA 位点发现」的说法收回。**

- chr20 三 seed 平均，lnc：S50 Sn **0.064** / Pr **0.094**（规则要求 Sn ≥ 0.15 才称位点发现，≥ 0.08 且 S25 ≥ 0.20 才称候选位点发现）；S25 Sn 0.134 / Pr 0.198。chr9（v2.0）重复：S50 0.069 / 0.108，S25 0.140 / 0.218。
- 原 L1 的 0.306 / 0.422 里，约五分之四的命中是「碰到了」而不是「定位了」：预测与真值基因的跨度对不上。
- 相对优势仍在：GENATATOR 的 lnc S50 Sn 是 0.006（我们约 10 倍），SegmentNT 0.008。但绝对值太低，倍数撑不起位点发现的说法。
- 口径本身不算苛刻到无法达到：同一口径下 GENCODE v41 对 v50 的 lnc 是 0.396（原 L1 0.471，几乎不掉），mRNA 0.973；GENATATOR 的 mRNA 0.794，Tiberius 0.653（它只出 CDS，跨度天然短于含 UTR 的基因跨度）。我们的 mRNA 是 0.55。

## 3. 为什么掉这么多（描述）

- **预测与真值的跨度对不上，而且三个 seed 错的方式不同。** chr20 上，预测跨度与其重叠最大的真值 lnc 跨度之比的中位数：seed 42 为 2.61（过长、吞并邻居），seed 123 为 0.97，seed 456 为 0.30（碎、短）。此前文档里的「预测跨度是真值的 2.8 倍」只对 seed 42 成立。
- **端点偏差大。** lnc 的 TSS / TES 偏差中位数 7.7–9.5 kb / 9.3–21 kb（chr20），chr18 为 13–22 kb / 19–31 kb。同一批模型的 mRNA 是 1–2 kb / 1.6–2.4 kb；GENATATOR 的 mRNA 是 79 bp / 21 bp。
- **吞并。** 在按 L1 命中的 lnc 预测里，一个预测同时命中 ≥2 个真值 lnc 的比例：seed 42 为 30%（最多 7 个），seed 123 为 14%，seed 456 为 8%。
- 能配上的那一小部分定位并不差：S50 匹配对的跨度 IoU 中位数 0.60–0.70。

## 4. 对论文的影响

1. 主文不能再用 L1 的 0.306 来说「发现了三成 lncRNA 基因位点」。可以说的是：模型报出的 lnc 区段有四成多与注释 lncRNA 外显子同链重叠（GENATATOR 的 11 倍召回），但只有约 6–7% 的注释 lncRNA 被一个预测以合理的跨度单独对上。
2. 这把问题从「结构定不下来」前移到了「**位点的范围就定不准**」。S1b 当时的结论（瓶颈是剪接而不是边界）是在给定真值边界的前提下得到的，不矛盾，但端到端看，边界是先于剪接的一道坎。
3. 新位点验证（全基因组推理那一项）的价值判断要重做：候选是「转录相关区段」，验证时必须用两端证据与全长转录本来定义单位，不能沿用预测的边界。
4. 相对基线的优势在任何口径下都在（约 10 倍），这一点保留。
5. 模型侧最直接的改进目标变成边界：TSS / TES 定位和相邻基因的切分。v1.6 的边界头只带来 AUPRC +0.024，没有解决这个问题。
