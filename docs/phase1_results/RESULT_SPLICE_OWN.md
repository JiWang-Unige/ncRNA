## 结论

- **按事先写定的判据，仍「未达有效」**。没有一个 w 同时过结构线和精度护栏，与上午的 SpliceAI 诊断结果一样。
  - w = 1：lnc L3 剪接点 Sn 0.102，三个 seed 都升，过了结构线；但严格 Pr 0.337，没过护栏（≥ 0.40）。
  - w = 0.5：严格 Pr 0.418，lnc L1 Sn 从 0.286 升到 0.375，守住护栏；但 L3 Sn 只有 0.053，L2 Sn 只有 0.008。
  - w = 2：两条都没过。
- **自训网络在真位点上打分高得多，解码结果却和 SpliceAI 几乎一样**。
  - chr18 真值 lnc 剪接点的中位分数为 0.45–0.50，SpliceAI 为 0.12–0.14。
  - 但拿到解码里，三个 w 的 lnc L3 / L2 / 严格 Pr 都与 SpliceAI 相差不到 0.02（第 3 节）。
- **原因：它把真位点和假位点一起抬高了，区分能力只略好于 SpliceAI**。
  - 用同一个函数算 chr18 lnc 剪接点的 AP：候选为满足基序的位置，去掉 mRNA 位点。自训网络为 0.161，SpliceAI 为 0.140。
  - 也就是说，基序位置上有大量未注释的位置得分与真 lnc 位点一样高。解码器在这些位置照样切内含子。
  - seed 42、w = 0.5 时，命中真值的预测上「两端都对不上真位点」的内含子从基线的 1,186 个增加到 2,358 个；用 SpliceAI 时为 1,822 个。
- **结构瓶颈仍在剪接信号的区分能力上**。
  - 真值上限（上午的结果）：剪接点完全已知时，L2 可到 0.071，严格 Pr 0.759。
  - 两个只看序列的剪接网络（SpliceAI，以及专门加了 lnc 位点训练的自训网络）都把 lnc 位点 AP 停在 0.14–0.16，离这个上限很远。
- **对 v2.0 的含义**：按草案情况 B 定稿，v2.0 默认不含剪接项。是否把剪接项作为 chr9 上的预注册消融（只报告），由用户在冻结卡上决定。

## 6. 对下一步的含义

- **v2.0**：按 `DRAFT_V20.md` 情况 B 定稿，默认不含剪接项。冻结卡上请用户选「不含」或「只作消融」。
  - 若选消融：权重固定为本次选中的 S10k，w 固定为 0.5。chr18 上两套剪接分数都只有 w = 0.5 守住护栏。在 chr9 上与基线并列报告，不参与判定。
- **论文**：两次 chr18 诊断与真值上限可以合成一个结论：lnc 结构的瓶颈是剪接位点的区分能力；只看序列的剪接网络，即使专门用 lnc 位点训练，也只把 lnc 位点 AP 从 0.14 提到 0.16。剪接点已知时，同一模型和解码器能越过 Strong 的 L2 线。
- **没有提议的方向**（只记录，不排进计划）：
  - 用 RNA-seq junction 作外部证据。这会把方法从「只看序列」变成证据驱动，改变论文定位。
  - 加大剪接网络或延长训练。chr22 曲线已接近平台，预计收益小。
  - 在内含子长度、外显子数上加先验，抑制过碎的切分。这要在 chr18 上调参，可以作为 v2.1 的候选。

## 7. 局限

- 训练标签只有 GENCODE v50。未注释的真剪接点被当成负例，chr18 上的 AP 也把它们算作假阳性，绝对值偏低。生物学验证（`RESULT_BIOVAL.md`）显示，约一半新位点的区间内有剪接读段。
- 只试了一种结构、两个上下文长度，10 个 epoch。
- w 网格和事后分析都在 chr18 上做，只代表可达上限。
- 第 5 节只拆了 seed 42。
- 诊断运行期间 Tiberius 也在 GPU 上，约 8.7 GB，略超本项目 30% 的显存上限（约 7.3 GB），持续约 20 分钟。它不影响诊断结果。
