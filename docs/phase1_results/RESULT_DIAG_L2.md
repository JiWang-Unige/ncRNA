# RESULT v1.5：lncRNA 内含子链（L2）为何几乎全错（协议 §12；2026-10-21）

## 一句话结论

**按预注册规则，B（结构）和 C（两端）同时成立，A（剪接点精度）不成立 → 需要 G2。**
lnc 预测的主要毛病不是剪接点“差几个碱基”，而是**转录本没有在正确的位置结束**：预测基因的跨度中位数是真值的 2.8 倍，过半跨过 ≥ 2 个真值基因，72% 的预测内含子落在配对真值的跨度之外。真值跨度内部的外显子摆放也不对（覆盖率中位数 0.40）。

## 材料与执行

- checkpoint：P1-S2 臂 R、seed 123（AUPRC 中位的 seed），代理特征（GENERanno 第 23 层 PCA-512）。
- 整条 chr18，S3 解码（外显子 ≥ 20、内含子 ≥ 50、lnc ≥ 200 nt），与 P1-S2 设置完全一致。
- **复现核对**：lnc 预测 214 条、L1 Pr 0.486，与 P1-S2 记录完全相同；mRNA 预测 896 条（记录为 895，差 1 条，属数值非确定性）。
- **执行位置偏离**：协议写的是在 ont CPU 上解码。实际 ont 负载约 60/32 核，CPU 上 GRU 势能计算预计需约 5 小时，因此改在 Kaggle castwj 的 GPU 上跑同一脚本（约 10 分钟，kernel `ncrna-diag-l2-r-123`）。仍属“只用 CPU 和 Kaggle”，没有读 chr20。
- 产物：`results/DIAG_L2/diag_r123.json`（预注册诊断 1–6 与判定）、`explore_r123.json`（探索性补充，见下文）；GFF3 在 ont `outputs/PHASE1/DIAG_L2/kaggle_r123/`。

### 判定（lnc，规则只看 2–4）

| 规则 | 条件 | 观测 | 是否成立 |
|---|---|---|---|
| A 边界精度 | 1–20 bp 偏差 ≥ 50% | 2.5% | **否** |
| B 结构 | 单外显子比例 ≥ 50%，或外显子覆盖中位数 < 0.5 | 3%；**0.40** | **是**（由覆盖率触发） |
| C 两端 | 跨度覆盖中位数 < 0.5，或 TSS/TES 中位数 > 1 kb | 0.97；**9.8 / 17.0 kb** | **是**（由 TSS/TES 触发） |

按 B → C → A 的优先顺序：**进入 G2**，先解决结构，再解决两端。

**坐标约定已排除**：同一份 GFF 中 mRNA 的预测内含子 71.5% 与真值完全一致，说明解码、坐标（1 基）和比对代码都没有系统偏移；lnc 的失败是模型层面的。

## 探索性补充（不参与判定，用于指导 G2 设计）

| 项 | lncRNA | mRNA |
|---|---|---|
| 预测跨度 / 真值跨度（中位数，q25–q75） | **2.77**（1.05–5.99） | 0.12（0.004–0.75） |
| 预测跨过 ≥ 2 个真值基因（任意类型、同链）的比例 | **56%** | 18% |
| 预测内含子落在配对真值跨度**之外**的比例 | **72%**（202/280） | 4%（111/2,909） |
| 跨度**之内**的预测内含子：0 bp | 15% | 74% |
| 　　　　　　　　　　　　　> 100 bp | 67% | 16% |
| 真值内含子被精确找回（均值） | 3.4% | 26% |
| 每个被命中真值基因对应的预测数：1 / ≥ 2 | 101 / 7 | 116 / 142 |

解读：

1. **lnc 的主因是“停不下来”**。预测的 lnc 基因从真值位点出发，用很长的内含子（中位 18 kb，真值 4 kb）继续延伸，常常把相邻基因并进来。所以大多数预测内含子根本不在真值转录本的范围内，L2 自然为 0。这是 G1 的结构性弱点：内含子和基因间区的长度只能是几何分布，也没有“基因在这里结束”的显式事件（TES）和基因级打分。
2. **跨度之内也只有 15% 的内含子是精确的**（mRNA 是 74%）。在代理特征下，lnc 的剪接信号本身就弱；这一部分可能随正式特征（第 17 + 23 层、4,096 维）改善，不能全部归给语法。
3. **mRNA 呈现相反的问题：碎片化**。剪接点基本准（74% 精确），但一个真值基因常被切成多段（55% 被命中的基因对应 ≥ 2 条预测，跨度比中位 0.12）。G1 同样缺少把整条基因连起来的基因级证据。
4. 两类问题都指向同一个缺口：**基因级与片段级打分 + 显式长度分布 + TSS/TES 事件**，正是 G2 设计文档 §2 的内容。

## 局限

- 代理特征、单个 seed、lnc 只有 104 条配对预测和 280 个预测内含子；比例的置信区间较宽。不过 A 与 B/C 之间的差距很大（near-miss 2.5% 对阈值 50%；TSS/TES 偏差约为阈值的 10–17 倍），结论对抽样误差不敏感。
- 外显子覆盖率 0.40 只比阈值 0.5 低 0.1；B 的成立主要靠这一项。即使 B 不成立，C 也足以指向 G2 的 TSS / TES 候选机制。
- “跨度之内仍多为 > 100 bp”的部分可能有特征强度的贡献，需要在正式特征上用 G1 与 G2 的对照来分离。

## 对 G2 的具体要求（建议写入协议 v1.6）

按诊断结果，G2 设计文档中的组件优先级调整为：

1. **TES / TSS 事件与基因级分**（直接针对“停不下来”和合并邻居）：τ_TSS、τ_TES 候选加基因级 ρ_k(外显子数, 成熟长度)。
2. **分桶的内含子 / 基因间区长度分**（针对预测内含子 18 kb 对真值 4 kb）。
3. 外显子片段分与长度分（针对跨度内覆盖率低）。

同时按规则 C 的要求，准备一个**低成本的 G1 对照**：G1 + 边界头（TSS / PolyA 通道，作为额外势能）。v1.6 中两者在相同代理特征、相同 chr18 评估、3 个 seed 下比较，替换判据沿用 G2 设计文档 §4（AUPRC_lnc 至少 +0.02、L2 Sn 更高、3 个 seed 同号）。
