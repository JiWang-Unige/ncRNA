# PLAN REP20：端点分析在 chr20 上的复现（冻结 2026-11-14）

> **冻结**：用户 2026-11-14 在对话中回复「chr20 复现端点分析」。本计划在任何 chr20 端点读数产生之前提交；读数、判据与模型均不再改。
> 起因：引言/讨论草稿的局限 (ii)——第 13–15 节（S11、BND、END）只在开发染色体 chr18 上做过。chr20 是测试染色体，检出结果已读过一次；本计划**只做新的描述性读数，不调任何参数、不选模型、不改解码规则**。
> 范围：第 14 节（BND：后验里有无端点信号，以及三个排除项）和第 15 节（END：阶段 0 边界头 + 4 个已训练探针的端点定位、CpG 分层、终点）。第 13 节（S11 / S1B，结构对端点误差的容忍度）不在本次范围：S11 依赖 GENATATOR 的分割模型，chr20 是否在其训练集中未核实。

## 2. 事前判据（「复现」的定义）

读数与 chr18 完全相同（`PLAN_BND.md`、`PLAN_END.md` 第 3 节）。判据：

| 编号 | 对应正文 | 复现条件 |
|---|---|---|
| R1 | 第 14 节「后验无 lnc 端点信号」 | 3 个 v1.9 模型平均：检出基因中 lnc 起点后验起点 ≤ 1 kb 的比例 < 0.30，且 mRNA ≥ 0.60 |
| R2 | 第 14 节三个排除项 | 接缝、解码器（S1）、真值端点三条按 `PLAN_BND.md` 的同一阈值仍「不成立」（`holds = false`） |
| R3 | 第 15 节 CpG 分层 | 7 个来源（3 个阶段 0 + 4 个探针）中 ≥ 6 个满足 Q4 > Q3 > max(Q1, Q2)，且 7 个来源平均的 Q4 − max(Q1, Q2) ≥ 0.10 |
| R4 | 第 15 节终点不可定位 | 7 个来源中，有 polyA 的 lnc 终点和 mRNA 终点的 Loc1k 都 ≤ 0.15 |

- 四条都满足：正文写「replicated on held-out chr20」。
- 部分满足：如实写哪条复现、哪条没有；不满足的那条在正文降级为「chr18 上观察到」，不再加实验去挽回。
- 描述性读数（不作判据）：有 CAGE 的 lnc 起点在阶段 0 / P-ann / P-ev 下的 Loc1k，以及 `PLAN_END.md` 第 4 节 A/B/C 规则在 chr20 上的结果；它们不改变第 15 节「两种改进办法不下结论」的写法。

## 3. 计算与资源

- **特征**：chr20 的 GENERanno 缓存（`data/p1_feat/chr20.npy`）已删除，需用原脚本重算（`p1_feat_ont.sh`，`CHROM_ONLY=1 NAMES=chr20`，用新的完成目录以免被旧完成标记跳过）。约 3,148 个 tile、约 88 GB。之前 chr20 的分片记录给出每 tile 0.12 s（不含模型加载），预计总 GPU 时间 < 1 小时。
- **磁盘**：ont 剩约 143 GB。启动前要求剩余 ≥ 120 GB；chr20 读数完成后**立即删除 chr20 特征**（与之前一致），只留边界 logit / 探针输出（约 6 GB）。
- **GPU**：全部经 `gpu_gate.sh`，TE 进程运行时等待；单个前向约 3 分钟/模型。合计 < 1.5 GPU 小时。
- **重算特征的一致性检查**：重算前，P1.5 读数时的 chr20 分片 JSON 记有 sha256；新特征逐分片比对 sha256（或在不一致时报告余弦），作为「输入与检出读数时一致」的证据。v1.9 的 BND 读数不依赖新特征。
