# S3 前半结果：v1.9 靠什么找到 lnc 位点（相关分析，2026-11-04）

> 计划：`PLAN_S3.md`，在读数前冻结（ee919ef）。决定卡 `subjournal-portfolio` 第一项。
> 运行：ont CPU，11-04，每条染色体约 30 秒。脚本 `scripts/phase1/s3/s3_features.py`；事后检查 `s3_posthoc.py`，**在读过主结果之后写的**。
> 原始输出在 ont `outputs/PHASE1/S3/`，汇总在 `docs/phase1_results/S3/`。只读已有的 P1.5 预测，不重新解码，也没碰 chr9。
> 主分析在 chr18。chr20 用的是 11-01 已读出的预测，只作描述性重复。

## 结论

- **两条染色体上一致的关联（冻结口径，按「相关」定义）**：
  - **启动子 CpG**：系数 +0.35（chr18）/ +0.34（chr20）。最高四分位的检出率 0.41 / 0.42，最低四分位 0.22 / 0.24。
  - **基因跨度**：+0.55 / +0.70。检出率从最短四分位的 0.13 / 0.12 升到最长四分位的 0.48 / 0.54。
  - **成熟长度**：+0.31 / +0.19。
  - CAGE、重复序列比例、外显子数（chr18）、单 / 多外显子都**不独立相关**。CAGE 单变量时检出率 0.40 对 0.25，但被 CpG 和长度解释掉了。
- **只在一条染色体上成立的（不当结论）**：
  - polyA 证据：chr18 +0.19，chr20 0.01；
  - 年代：chr18 −0.19，chr20 −0.07；
  - 年代 × 长度的交互项：只有 chr18；
  - 外显子数：只有 chr20 +0.17。
- **冻结设计有一个缺陷，如实报告**：`u1_pas` 就等于 `u1_kb − pas_kb`，三者完全共线。主表里这三项的系数分不开，L2 正则只是把权重在它们之间平分了。
  - 主表里 `u1_pas` 在 chr18 上按定义算「相关」（+0.08，CI [0.015, 0.149]）。chr20 上 CI 也不含 0，但 3 个 seed 方向不一致。
  - 由于共线，这条不作为结论。
- **事后检查（读过主结果之后加的，只作描述，不改判定）**：
  - 去掉 `u1_pas` 后，**U1 位点密度**系数为 +0.12 / +0.13，两条染色体上 CI 都不含 0；但 seed 42 的方向相反，仍不满足「相关」定义。PAS 为负（−0.12 / −0.08），CI 跨 0。方向与 Almada 2013 的 U1–PAS 轴一致，但证据不够硬。
  - **CpG 的效应不是来自与 mRNA 共享启动子**：加入「与反向 mRNA 头对头（1 kb 内）」「与反向 mRNA 基因体重叠（反义）」「到最近 mRNA TSS 的距离」后，CpG 系数仍为 +0.36 / +0.37。
  - **反义 lnc 明显更难找到**：系数 −0.26 / −0.29，两条染色体都满足「相关」定义。检出率 0.18 / 0.20，其余 lnc 为 0.30 / 0.31。头对头的 lnc 检出率最高（0.39 / 0.39），但它们的 CpG 本来就高（o/e 0.70 / 0.62，其余约 0.30），控制 CpG 后头对头本身不再独立相关。
- **含义（解读，供论文讨论）**：
  - v1.9 找到的 lnc 位点，偏向有 CpG 富集启动子、跨度长的基因。也就是说，它主要靠「像基因的启动子 + 长转录单元」来定位，而不是靠外显子序列本身。这与 S1b 一致：外显子 / 剪接结构从序列上定不下来，位点则靠启动子和长度这类信号。
  - 与编码基因反义重叠的 lnc 更难找到。可能的原因是：同一区段的编码态（另一条链）在语法里与 lnc 态竞争。这一点没有直接验证。

## 4. 局限

- 相关不是因果。计算机内突变（S3 后半，GPU）可以检验模型是否真的用到了 CpG / U1 信号，要另写计划。
- 「检出」依赖 τ*，并且三个 seed 的检出率差别不小（0.21–0.40）。
- 特征窗口（± 500 bp、1 kb、± 200 / 100 bp）是预先定的，没有扫描。
- 「年代」按基因 ID 判定。v47 的 CLS 导入可能改动了老基因的 ID，这会让年代变量不干净。
