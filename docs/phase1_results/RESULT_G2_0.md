# RESULT G2-0：候选生成与召回上限门（协议 v1.6 §13；2026-10-22）

## 一句话结论

**预注册的召回门通过**：验证集 lnc canonical 内含子召回为 94.5%，门槛是 90%。

**但候选剪枝基本失效**：为达到 99% 的剪接召回，阈值必须低到约 1e-22，候选几乎等于全部满足 motif 的位点。每个 24.5 kb 窗口有约 7,900 个节点，带来两个后果：

- 回看 256 个起点时，只有 65% 的 lnc 内含子在格上可达；
- 训练开销远超协议的 4 T4 小时上限。

按协议“先优化再上 Kaggle”，现在**不能**直接跑 G2-3 × 3 seed。需要你在下面的选项中做决定。

## 执行

- 候选来源：G1B seed 42 的 checkpoint（冻结）。seed 123 已训练完，seed 456 等 Kaggle 配额刷新。
- 后验计算：castwj 本周 GPU 配额已用完，改在 ont CPU 上进行，使用新增的 `g1.marginals_np`（numba、float64 的稀疏前向–后向；与暴力枚举和 float64 torch 实现逐项一致），约 5.5 秒/窗口。
- 阈值在 2,000 个训练窗口上设定，然后用于 300 个验证窗口。
- **正式判读前修正的两个实现错误**（都不是设计改动，已记入偏离记录）：
  1. 候选分数原本用 float16 存储。真实剪接位点的后验有 13–18% 低于 float16 的下限（约 6e-8），存下来变成 0。已改为 float32。
  2. `choose_theta` 里有一个我自己加的 1e-6 下限，把阈值从训练集的真实 1% 分位（约 1e-22）抬高了，验证召回因此掉到约 79%。协议只规定“召回 ≥ 99%”，已去掉这个下限。

## 原因

- 代理特征下，G1B 对真实剪接位点的后验分布极宽：中位数 0.06–0.35，但 1% 分位低到约 1e-23。要保住 99% 的召回，只能接受几乎所有 motif 位点作为候选。
- 这与 v1.5 诊断一致：即使在真值跨度之内，预测内含子也只有 15% 精确。剪接定位本身弱，稀疏候选的前提（“真实事件集中在少数高分位点”）不成立。
- 候选一旦稠密，256 个起点的回看只能覆盖约 3 kb，而 lnc 内含子中位长度约 4 kb，于是有约三分之一的真实内含子在格上不可达。

## 选项（需要你决定）

**A（推荐）：G2-PH，逐碱基的相位型（phase-type）半马尔可夫语法**
- 不用候选格，而是在 G1 的状态空间上展开：外显子按角色（单 / 首 / 内部 / 末）分组；每个角色和内含子用 2–3 个串联状态表示长度，学成非几何的长度分布（负二项型；内含子可用短 / 长两支的混合）；TSS / TES 边界分沿用 G1B。
- 训练用新写好的 float64 numba 前向–后向。G1 的 17 状态版本实测约 0.03 秒/窗口（CPU 单线程，24.5 kb）；展开后约 70 个状态，转移依然稀疏，按状态数线性外推约 0.1–0.2 秒/窗口。GPU 只负责 C0 头。
- 没有回看上限，也不受候选密度影响；对外显子 / 内含子长度与基因结构的建模，正是 v1.5 诊断指出的缺口。
- 代价：片段级 MLP（原 G2-3）无法在逐碱基框架里表达，需要删去或改成逐碱基特征；分级消融相应改为“角色 + 边界（几何）→ + 相位型长度”。需要写成 v1.7 并由你批准。约 1–2 天实现。
- 已完成的 `grammar/g2.py`（候选格，19 项暴力测试通过）保留：正式特征上剪接信号更强时，候选格可能重新可行。

**B：保留候选格，但用专门的剪接头生成候选**（对 P1-G0 的供体 / 受体通道训练 BCE，而不是用 G1B 后验），同时扩大回看并做 GPU 内核优化。密度能降多少未知，回看问题仍在，工程量更大。

**C：暂停 G2**，先等 G1B 的 3 个 seed 结果，等正式特征阶段再回到 G2。
