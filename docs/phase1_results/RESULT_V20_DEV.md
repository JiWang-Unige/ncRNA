## 结论

- **数据与重训按冻结的执行细节完成**：
  - 154 个 chr9 窗口原位替换为 lnc 63、编码 51、随机 40 个新窗口，均不在 chr9。
  - 未替换的 2,846 行，codes、四种 bits、events 与 p1v12 逐位相同。
  - 三个主模型 v20-g1b-42 / 123 / 456-ke 都训完 12 个 epoch。重启后核对过，第 10–12 epoch 的权重都能正常加载。
  - 补抽脚本第一次运行失败，是我的解包错误，已修复（2b91d0e），没有改动规则。
- **校准有效，按保留规则保留**：三个模型合计 2,974 个 lnc 预测，命中 1,141 个。

  | 折外（chr18 两半交叉拟合） | AUPRC | ECE |
  |---|---|---|
  | 原始置信度 | 0.422 | 0.294 |
  | 校准概率 | **0.507** | **0.039** |

  - 前半 / 后半分别为：AUPRC 0.458 → 0.560 / 0.389 → 0.498，ECE 0.272 → 0.072 / 0.312 → 0.070。
  - 系数（标准化后）：外显子数 +0.40，外显子上的 mRNA 后验 −0.37，log ORF +0.11，log 长度 +0.10，六聚体 −0.04，Fickett −0.03，ORF 占比 −0.01，**原始置信度 −0.002**。
  - 也就是说，在这些特征面前，模型自己的置信度几乎不带额外信息；起作用的主要是外显子数和「有没有落在编码态上」。
- **问题：按冻结的 τ 规则（网格 0.2–0.9，步长 0.1）选出的 v2.0 工作点不合适**：

  | 工作点（chr18，3 seed 平均） | τ | lnc Sn | 严格 Pr |
  |---|---|---|---|
  | 基线（原始置信度） | 0.7 | 0.236 | 0.437 |
  | v2.0（校准概率） | 0.4 | **0.189** | 0.507 |

  - 校准后的概率集中在 0.3–0.5，τ 从 0.3 到 0.4，Sn 就从 0.338 掉到 0.189。
  - 这个工作点在 chr18 上已经低于 Go 的 Sn 门槛（0.20），也比基线低 0.047，超过 chr9 精度判据允许的 0.03。照此读 chr9，Go 复现和精度两条很可能不过，原因是**规则粒度**，而不是校准无效。
- **细网格的 τ 曲线（事后，只用 chr18）显示校准改善了精度与灵敏度的取舍**，越往高精度一端改善越大：

  | Sn 大约 | 基线 Pr（τ） | v2.0 Pr（τ） | 差 |
  |---|---|---|---|
  | 0.30 | 0.415（0.50） | 0.425（0.33） | +0.01 |
  | 0.27 | 0.430（0.62） | 0.456（0.35） | +0.03 |
  | 0.24 | 0.435（0.69） | 0.479（0.37） | +0.04 |
  | 0.20 | 0.430（0.77） | 0.498（0.39） | +0.07 |

- **需要用户决定（读 chr9 之前）**：τ 的选法，见决定卡 `v20-tau`。三种做法都只用 chr18 的信息：
  1. **不改**：τ_base = 0.7，τ_v20 = 0.4，按冻结规则读 chr9。预计 Go 与精度两条不过，校准一条可能过。
  2. **同一规则、细网格**（步长 0.01，两臂都用）：τ_base = 0.62（Sn 0.267 / Pr 0.430），τ_v20 = 0.34（0.285 / 0.441）。v2.0 的 Sn 和 Pr 都高于基线，但 Pr 只高 0.011，chr9 上 Δ 的 CI 下界 > 0 的可能性不大。
  3. **按 chr9 精度判据选点（推荐）**：基线用细网格的 §16 规则（τ_base = 0.62），v2.0 取「Sn 不低于基线 Sn − 0.02 的 τ 中严格 Pr 最高者」，留 0.01 的余量给 chr9 上的波动。
     - chr18 上为 τ_v20 = 0.36：Sn 0.253 / Pr 0.471。相对基线 ΔPr +0.041，ΔSn −0.014。
     - 这把冻结的 chr9 精度判据「Pr 提升、Sn 降幅 ≤ 0.03」直接变成选点规则，并且仍满足 Go 的两个门槛。
