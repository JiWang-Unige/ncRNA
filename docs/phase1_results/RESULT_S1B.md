# S1b 结果：lnc 结构失败的分解，边界 vs 剪接（chr18，2026-11-04）

> 计划：`PLAN_S1B.md`，判据在读数前冻结（4eb3667）。决定卡 `subjournal-portfolio` 第一项。
> 运行：ont，11-04 10:49–11:58 CET，10 个作业。脚本 `splice_diag.py --span-oracle` / `--oracle`，队列 `s1b_queue.sh`。
> 原始输出在 ont `outputs/PHASE1/S1B/`，汇总在 `docs/phase1_results/S1B/`。只用 chr18，chr9 / chr20 没碰，没有训练、没有调 γ / τ。

## 结论

- **复现核对都通过**：
  - A0 用改过的脚本、w = 0 重跑 seed 42，后验 sha256 与 P1.5 chr18 读取一致。
  - A2 seed 42 的 genes.json 与 11-03 SPLICE_DIAG 的 `g1b-42-ke_oracle` 一致。
- **判定（写定规则）：「剪接是主要瓶颈」**。A2 的 L2 高于 A1，且 A1 < 0.05。按规则**不做 S11（两阶段解码）**，结构部分按 S1 的结论写。
  - 给了真值边界（A1）：两端偏差中位从约 20 / 27 kb 降到约 1 kb，严格 Pr 升到 0.96。但 lnc L2 仍为 **0.003**，剪接点精确度只有 0.026。**位点和两端都对了，内部结构仍然是错的。**
  - 给了真值剪接位点（A2）：lnc L2 **0.168**（3 seed：0.071 / 0.146 / 0.287），剪接点 P / R 0.61 / 0.22。
  - 两者都给（A3）：lnc L2 **0.341**，严格 Pr 0.999。
- **更正一个旧数字**：11-03 写的「真值剪接上限 L2 0.071」只是 seed 42 一个模型的数。3 个主模型平均是 0.168，seed 之间差别很大。RESULT_SPLICE_DIAG 和看板里引用到的地方要一并改。
- **含义**：
  - 解码器本身能把正确的剪接位点变成正确的 lnc 结构：真位点就能给 L2 0.17，再给边界能到 0.34。
  - 瓶颈在剪接位点能不能从序列上区分出来。这正是 S1 要量化的。
  - 任何能更好区分 lnc 剪接位点的序列模型，都可以经同一个解码器直接变成结构增益。AlphaGenome 的剪接位点 AP 因此值得在 credits 更新后作为对照测一下。但按其条款，它不能进我们的方法。

## 2. 读法

- **边界不是瓶颈**：A1 把两端拉到约 1 kb 以内，但外显子覆盖只从 0.50 升到 0.61，内含子链几乎没有对的。说明在正确的基因区间里，模型的 lnc 外显子 / 内含子后验仍然分不出真外显子。
- **剪接位点是瓶颈**：只给真位点，外显子覆盖就到 0.86，内含子链 0.17。剪接点精确度从约 0.01 升到 0.61，但召回只有 0.22，因为解码器仍要在真位点之间选组合。
- **两者叠加**：A3 的 0.34 约是 A2 的两倍。边界对已有正确剪接位点的模型有帮助，对没有的没有帮助。
- **与 GENATATORs 的已知区间设定对照**（不同染色体、不同真值，只作量级参考）：它在 T2T chr20 的已知转录本区间内，外显子结构完全正确 25.6%。我们给出真值边界后，内含子链为 0.003。这个差别提示：它的分割头在已知区间内用上了我们模型没有用上的外显子信号。可能的原因是训练目标不同（它做转录本内分割，我们做全染色体解码），以及口径不同（它要求外显子完全一致，我们的 L2 只看内含子链）。这些都没有验证。这是一个值得在论文里讨论的对照，但不改变本判定。

## 3. 局限

- chr18 是开发染色体，真值剪接位点与真值边界都是不现实的上限设定，只用于分解，不是可达性能。
- 每个设定只解码一次，γ / τ 沿用 v1.9 的值，没有为约束设定重新选。A2 / A3 的 lnc 报出数比 A0 多约一倍，严格 Pr 会受 τ 影响。
- seed 间差别大（A2 的 L2 从 0.071 到 0.287），3 个 seed 不足以给出稳定的上限估计。
