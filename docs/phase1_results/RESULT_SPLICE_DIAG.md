# chr18 剪接势能诊断：SpliceAI 分数接入 v1.9 解码（探索性，2026-11-03）

> 来源：用户 2026-11-03 在决定卡 `p15-next` 上的决定，第 ① 条。只用 chr18（开发集），不重训，结果只作诊断。
> SpliceAI 训练时用过 chr18 和 chr20，这里的数字不能当成泛化证据，更不能当 chr20 的结果。
> 代码：`scripts/phase1/splice_diag/`（GitHub 89cbf71、9abecd2 及本次提交）；输出：ont `outputs/PHASE1/SPLICE_DIAG/`。

## 结论

- **按看结果前写定的判据，诊断「未达有效」**。没有一个权重同时满足结构线（三个 seed 都升，且 3 seed 平均 lnc L3 剪接点 Sn ≥ 0.10 或 lnc L2 Sn ≥ 0.05）和精度护栏（lnc L1 Sn 降幅 ≤ 0.03、严格 Pr ≥ 0.40）。
  - w = 1：L3 Sn 0.101，过结构线，但严格 Pr 0.349，没过护栏。
  - w = 0.5：严格 Pr 0.423，守住护栏，但 L3 Sn 只有 0.055。
- **剪接信号确实有用，但不够**。w = 0.5 时：
  - lnc L3 剪接点 Sn 从 0.002 升到 0.055，Pr 从 0.006 升到 0.089，三个 seed 都升。
  - lnc L1 Sn 0.286 → 0.353，严格 Pr 0.442 → 0.423，AUPRC_lnc 0.141 → 0.168。
  - 事后把每个 seed 报出的 lnc 数对齐到基线：L1 0.290 / 0.457，与基线持平或略好；L3 Sn 0.049。
  - lnc L2 内含子链 Sn 只到 0.010–0.012，离 Strong 线 0.05 很远。
- **剪接信息完美时（真值剪接点上限，seed 42）**：
  - lnc L3 Sn 0.151、Pr 0.540，lnc L2 Sn 0.071，严格 Pr 0.759，AUPRC_lnc 0.291。
  - 已检出的多外显子 lnc 里，17% 拿到完整内含子链（基线 0.4%）。
  - 即：只要剪接信号足够准，现有模型和解码器能越过 Strong 的 L2 线。瓶颈主要在剪接信号本身。
- **SpliceAI 的短板在 lnc**。chr18 真值剪接点上的分数中位数：mRNA 约 0.9，lnc 只有约 0.12，lnc 只有约 20% ≥ 0.5。调研（REVIEW_SPLICE_BASELINES.md A6）显示 lnc 剪接信号本来就弱，SpliceAI 又主要用编码转录本训练（后者未核实）。
- **mRNA 的提升要打折看**。w = 0.5 时 mRNA L2 Sn 0.052 → 0.235、L3 Pr 0.511 → 0.845，但这些位点 SpliceAI 训练时见过。

## 1. 做法

- **模型**：configs/p15_v19b.json 的三个主模型 g1b-42 / 123 / 456-ke，各用第 10–12 epoch 的权重平均。解码设定与 v1.9 相同：精确后验、外显子层面 MEA，γ = 3、τ = 0.6。
- **SpliceAI**：
  - 来源：PyPI spliceai 1.3.1，5 个模型取平均。为避免在 ont 上装 TensorFlow，在 PyTorch 里按导出的 Keras 网络结构复现推理。
  - 校验：与 Keras 参考输出的最大差 1.8e-6。
  - 打分：两条链分别打分，chr18 共 160 秒 GPU。
  - 位点约定：donor 记在外显子最后一个碱基，acceptor 记在外显子第一个碱基，以转录方向为准。在 chr18 注释上做偏移检查，偏移 0 处是唯一的峰。
- **势能**：
  - 加在内含子左右边界态上，大小为 w × [log max(p, 1e-6) − log π]。
  - π 是满足剪接基序的位置上的平均 SpliceAI 分数，约 7e-4–1e-3，分 donor / acceptor、分链。
  - mRNA 与 lnc 的边界态加同样的分数。
  - 加势能后重新算精确后验，再解码。
- **复现检查**：w = 0 时后验与 P1.5 chr18 读取逐位相同（sha256 一致），之后才跑其余变体。
- **真值上限**：把 SpliceAI 分数换成「真值剪接点处为 1、其余为 1e-6」，w = 1，只跑 seed 42。

- w ≥ 1 时置信度普遍被推高，按置信度排序不再可靠。

## 5. 事后分析 2：结构在哪丢（seed 42，最终预测）

| | 基线 | w = 0.5 | w = 1 | 真值上限 |
|---|---|---|---|---|
| 预测 lnc 数 / 其中 ≥ 5 个外显子 | 364 / 177 | 507 / 290 | 997 / 673 | 415 / 132 |
| 检出的多外显子真值 lnc | 241 | 294 | 388 | 353 |
| 其中至少一个内含子完全对上 | 9.5% | 44.2% | 53.1% | 74.8% |
| 其中拿到完整内含子链 | 0.4% | 1.4% | 0.5% | 16.7% |
| 命中真值的预测上的内含子：完全对上 / 两端都对不上 | 24 / 1,186 | 246 / 1,822 | 394 / 4,395 | 772 / 77 |

- **基线的主要毛病是假内含子**：命中真值的预测上，绝大多数内含子两端都对不上任何真值剪接点，lnc 被切成了过多的外显子。
- **SpliceAI 能把一部分内含子拉到真位点上**，但抑制不住假内含子。lnc 的真位点 SpliceAI 打分低，基序处又有很多中等分数的位点，模型照样在那里切。
- **剪接信号完美时，假内含子几乎消失**。剩下的错误主要是配错位点（170 个内含子两端都在真位点上，但不是同一个内含子），即跳外显子或异构体。

## 6. 对下一步的含义

- 「直接把 SpliceAI 接进 v2.0」不够。按写定判据未达有效；它对 lnc 位点打分低，又只能用于诊断：chr18 和 chr20 都在它的训练集里，源码现行许可为 PolyForm Strict。
- 真值上限说明，现有模型和解码器在剪接信号足够准时，能越过 Strong 的 L2 线。最直接的方向是我们自己的剪接位点模型：
  - 用训练染色体上 v50 的 mRNA **和 lnc** 剪接点做正例；
  - 不碰 chr18（开发）、chr20（已读）和候选测试染色体 chr9；
  - 先用同一个外挂势能的流程在 chr18 上看能否达到上面的判据，再决定是否起草 v2.0。
- 这一步要不要做，交给决定卡 `splice-next`。

## 7. 局限

- SpliceAI 训练过 chr18，mRNA 的数字偏乐观。
- w 网格和事后分析都在 chr18 上做，只代表可达上限。
- 真值上限只跑了 seed 42。
- L3 的分母是所有转录本的内含子并集，单一预测转录本拿不满。
- 第 5 节只拆了 seed 42。
