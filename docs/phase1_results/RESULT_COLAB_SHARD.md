# Colab 分片路线验证（2026-10-23，决定 colab-topup 的前置步骤）

**结论：流程通过。** 瓶颈不在算力而在回传：Colab → ont 下载 7 MB/s。

| 项目 | Colab T4（fp16） | ont 4090（bf16，参考） |
|---|---|---|
| 20 个训练窗口 train_00000_00020 | 0.9 s/窗口，模型加载 86 s | 0.12 s/窗口，加载 4 s |
| sha256 | 一致 | — |
| 与参考的余弦（逐 token） | 中位 0.99996，1% 分位 0.99992，最小 0.99935（判据 ≥ 0.99） | — |
| 分片大小 / 下载 | 640 MB，88 s，7 MB/s | — |
| 花费 | 0.05 CU（余额 35.92 → 35.87），VM 已释放，无残留 | 7 s GPU |

**外推（提取）**：3,000 训练窗口 + chr18 + chr20 + T2T chr20 ≈ 13,000 个窗口/tile。
- Colab T4：约 3.3 小时、约 4 CU；但 290 GB 回传 ont 需 ~11.5 小时（7 MB/s）。
- ont 4090：约 26 分钟，免费；写到本地 NVMe（1.9 TB 空闲）。
→ 正式特征缓存应在 ont GPU 空闲窗口直接做（分片脚本可断点续跑、随时让路）；协议里"约 18 GPU-h"主要是训练与评估，不是提取。

**Colab 的合理用途**：训练/评估（不受 Kaggle 周配额限制），特征在 VM 内现算不回传：
每个 session 现算训练特征约 45 分钟 + chr18 约 1 小时 ≈ 2 CU 开销，再加训练本身。前提：VM 磁盘能放下约 160 GB（未测，下次 session 先 `df -h /content`）。
