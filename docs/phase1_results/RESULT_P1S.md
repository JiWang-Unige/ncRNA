# RESULT P1-S：代理路线筛选（协议 v1.1–v1.3；2026-10-21）

## 设定

- **特征与数据**：Phase 0 缓存的代理特征（GENERanno-1.2b-cds 第 23 层，PCA 降到 512 维）。训练用 2,000 个窗口；验证用 chr18 的 300 个窗口，真值取完全落在窗口内的 v50 基因，共 **86 个 lnc、2 个 mRNA**。
- **算力**：每个臂 6 个 epoch、seed 42，在 Kaggle castwj 的 T4 上跑，单臂约 50–60 分钟；S3 解码在 ont 的 CPU 上低优先级运行。没有读 chr20，也没有用 ont 的 GPU。
- **标签**：v1.2 版（canonical 转录本 + 可行性修复）。第一轮使用的有缺陷标签已作废，见协议 §9。

## 预先声明的规则：形式判读

| 规则 | 结果 | 形式上的结论 |
|---|---|---|
| 5 碎片化 | R 的预测数是真值的 8 倍，Pr 0.09 | 触发 → 已实现 S3；S3 下碎片化消失（预测数是真值的 0.3 倍） |
| 1 语法与 S1 | R − S1 = −0.068（标准解码）；S3 − S1 = −0.024 | 未达到 +0.02 → 按 v1.3 转向筛选 G2 |
| 2 并集与只有 lnc | R − S2 = −0.064（标准解码）；S3 下为 −0.017 | 未满足 R ≥ S2 − 0.01 → 只保留 lnc 通路 |
| 3 U-ev 与 F | S4 − R = +0.021（标准解码）；S3 下也是 +0.021 | 刚好越过 +0.02 → 主模型改用 F |

## 我的判断：这一轮筛选的统计功效不足，上述形式结论不应采纳

1. **验证集太小**：只有 86 个 lnc 基因，1 个基因对应 Sn 的 0.012。S3 下各臂之间的差距，只相当于 2 个基因左右。
2. **选 checkpoint 时的噪声占主导**：5 个臂的最佳 epoch 全是第 1 个，F1 随 epoch 波动 ±0.1，远大于臂与臂之间的差距。训练损失在下降（R 从 0.22 降到 0.057），但验证指标没有跟着改善，说明验证集太小、太偏（只含能完整放进 24.6 kb 窗口的短基因），无法反映模型的变化。
3. **L1 F1 会被碎片抬高**：规则 1 的比较受此影响（S1 产生了 5,863 个碎片）。按位点合并来算，S3 已经超过 S1（0.183 对 0.174）。
4. **S5（用更旧、更不完整的 v41 标签训练）在 S3 下反而最高**（F1 0.247）。这与预期相反，进一步说明各臂之间的排序主要是噪声。
5. 规则 6（差距在 ±0.02 以内就补 seed）本来就是为这种情况设的，但这一轮的问题不是缺一个 seed，而是验证集本身的功效不够。

## 稳健的收获

1. 发现并修复了**标签与语法的可行性 bug**（60% 的窗口不可行），这是正式训练前必须解决的问题（协议 §9）。
2. **碎片化**是没有长度建模时的主要失败模式。只在解码阶段加时长约束就能消除碎片，并第一次得到非零的内含子链召回；推理成本很低，在 CPU 上就能跑整条染色体。
3. 即便用的是弱代理特征和小训练集，S3 在 chr18 窗口上也达到了 lnc 位点 Pr 0.40–0.52、Sn 0.12–0.14。这与 GENATATOR 在 chr20 上的 0.42 / 0.028 不可直接比较（基因集和窗口限制都不同），但说明这条路线有机会在 precision 可接受的前提下做到明显不为 0 的召回。

## 下一轮筛选的改进建议（待用户确认后写入协议 v1.4）

1. **把验证集扩大到整条 chr18**（约 1,000 个 lnc 基因）：在 Kaggle 上提取 chr18 全长的代理特征（复用 Phase 0 的 PCA，约 11 GB，未超过 Kaggle 20 GB 的输出上限；T4 约 1.5–2 小时），并做整染色体解码。
2. **换用稳定的主指标**：基因级置信度（后验质量）的 PR 曲线 / AUPRC，加上位点合并 F1，减少对单一工作点和碎片的依赖。
3. **训练**：最多 12 个 epoch，加学习率余弦衰减；每个臂 3 个 seed；用整条 chr18 选 checkpoint。
4. 先用新设定复核 R / S1 / S2 / S4（都用 S3 解码），再决定是否需要 G2；G2 的设计（稀疏事件半马尔可夫）可以先写成方案文档。
