# RESULT BND：lnc 端点定位失败的诊断（2026-11-12）

> 计划：`PLAN_BND.md`（1b84511，读数前冻结）。脚本 `scripts/phase1/bnd/bnd_diag.py`。
> 运行：ont CPU，81 秒，chr18，v1.9 三个主模型已有的后验与预测。原始输出 `docs/phase1_results/BND/BND.json`。探索性诊断。

## 结论

四个候选原因里只有一个成立：**后验里就没有 lnc 的端点信号**。接缝、解码器、真值端点不可靠都被排除。

| 判断 | 读数（三模型平均） | 条件 | 成立 |
|---|---|---|---|
| 接缝是端点误差的主要来源 | lnc 预测端点落在接缝 ±100 bp 内 2.1%（均匀期望 1.0%） | ≥ 20% | 否 |
| 解码器丢了端点信息 | 逐碱基取大解码的 lnc S50 Sn 0.043，MEAX 0.054 | ≥ 2 倍且 ≥ 0.10 | 否 |
| 后验里没有 lnc 端点信号 | 后验检出的基因里 TSS 定位到 1 kb 内：lnc 22.7%，mRNA 69.6% | lnc < 30% 且 mRNA ≥ 60% | **是** |
| 真值端点不可靠占相当一部分 | lnc S50 Sn：两端都有证据 0.064，都没有 0.051 | ≥ 2 倍 | 否 |

## 1. 后验里的端点信号（D3）

M = 基因所在链上该类别基因状态的后验之和。

| | lnc（42 / 123 / 456） | mRNA（42 / 123 / 456） |
|---|---|---|
| 后验检出（跨度内 M 均值 ≥ 0.5） | 0.37 / 0.43 / 0.16 | 0.72 / 0.57 / 0.71 |
| TSS 台阶（内侧 1 kb − 外侧 1 kb，全部基因） | 0.04 / 0.06 / 0.05 | 0.39 / 0.35 / 0.40 |
| TES 台阶（全部基因） | 0.01 / 0.02 / 0.04 | 0.15 / 0.18 / 0.23 |
| 检出基因：TSS 起跳点距真值的中位数 | 10.0 kb / 8.5 kb / 2.9 kb | 390 / 358 / 389 bp |
| 检出基因：TSS 在 1 kb 内 | 0.17 / 0.18 / 0.33 | 0.69 / 0.72 / 0.68 |
| 检出基因：TES 终止点距真值的中位数 | 14.3 kb / 11.2 kb / 4.0 kb | 2.7 kb / 1.8 kb / 1.6 kb |
| 检出基因：TES 在 1 kb 内 | 0.07 / 0.11 / 0.27 | 0.28 / 0.36 / 0.41 |

- mRNA 的 TSS 在后验里是一个清楚的台阶（约 0.4），lnc 几乎是平的（约 0.05）。模型知道「这一带是 lnc」，但不知道它从哪里开始。
- TES 对两类都弱；mRNA 的 TES 也只有三四成落在 1 kb 内。
- seed 456 检出的 lnc 最少（16%），但检出的那些端点最准（TSS 中位 2.9 kb）；seed 42、123 检出多而端点差。检出率与端点精度在 seed 间此消彼长。

## 2. 错误类型（D1）与解码器（D2）

按 L1 被命中的真值 lnc 基因，与它重叠最大的 lnc 预测的关系：

| 模型 | 定位合格 | 预测过长 | 预测过短 | 错位 |
|---|---|---|---|---|
| seed 42 | 12% | **68%** | 7% | 13% |
| seed 123 | 24% | 38% | 24% | 14% |
| seed 456 | 18% | 17% | **56%** | 10% |

- 三个模型错的方向不同，说明这不是一个系统性偏置（比如先验偏长），而是模型在 lnc 的范围上没有稳定的依据。
- 换成逐碱基取大解码不改善（lnc S50 Sn 0.028 / 0.075 / 0.026，MEAX 0.033 / 0.089 / 0.039），mRNA 也略差。问题不在解码。

## 3. 接缝（D0）与真值端点（D4）

- 预测端点在小块接缝附近的比例是 1–3%，略高于均匀期望的 1%，可以忽略。
- 真值 lnc 的端点本身支持就少：最外侧 TSS ±200 bp 有 CAGE 峰的只有 16.8%，TES ±100 bp 有 polyA 簇的 32.7%；两端都有的只有 68 个（7%）。但即使在这 68 个基因上，S50 Sn 也只有 0.064，与都没有证据的（0.051）差不多。所以不能把定位失败归到真值不准。
- 一个正面的旁证：L1 命中的 lnc 预测，其起点 ±200 bp 有同链 CAGE 峰的比例是 8–11%，把起点平移 50 kb 后只有 0.3–0.6%（约 25 倍）。预测的起点远比随机位置更像真实的转录起始点，只是常常不是它所命中的那个注释基因的起点（那些基因自己的 TSS 有 CAGE 的比例是 21–29%）。

## 4. 含义

1. 端点问题是**训练侧**的：现有的监督（逐碱基状态标签 + v1.6 的 TSS / TES 事件头）没有让模型学到 lnc 的起止。事件头对 mRNA 有效（TSS 台阶 0.4），对 lnc 基本无效。
2. 可能的原因（未检验）：lnc 的 TSS 缺少 mRNA 那样的序列特征（只有 17% 有 CAGE 峰，S3 也显示检出主要靠 CpG 启动子）；注释的 lnc 端点里有相当一部分是长读长捕获得到的不完整转录本，作为训练标签噪声大；lnc 基因常比一个 24.6 kb 小块长，小块内看不到两端。
3. 不需要重训就能修的路（改拼接、改解码）都已排除。
4. 与 B1、S11 合起来的结论链：位点范围定不准（B1）→ 原因是后验里没有 lnc 端点信号（本诊断）→ 而现有区间分割模型需要 < 1 kb 的端点精度（S11）。所以端到端 lnc 注释的缺口是**lnc 转录起止的序列可预测性**。

## 5. 没做的 / 局限

- 没有直接看边界头的原始输出（读取时没有保存，需要 GPU 重新前向）；本诊断看的是它已经并入后的后验。
- CAGE 用的是 FANTOM5 峰，对低表达、组织特异的 lnc 覆盖不足，16.8% 是下界。
- 只在 chr18 上做；判读阈值是事前自定的。
