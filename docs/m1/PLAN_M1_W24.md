## 1. 问题

第 1 周的结果：
- 只用 DNA 的检出，简单 CpG 规则已接近我们（实验 2、长颈鹿）；
- 最强的序列模型也定不准低 CpG 起点；有 CAGE 证据、并且用匹配细胞类型的轨道时，能定位约 45%（实验 3 第二阶段）。

所以本阶段要回答：**在同一个细胞系里，少量便宜的端点测序（ssCAGE 起点、QuantSeq 3′ 端）加上我们的序列先验，能否把 lncRNA 从「区域」变成「转录单位」（S50）？并且是否胜过只用这些证据的简单做法？**

这对应 DECISION 的结果 B（方向 2）。如果不能，加上第 1 周的结果，就倾向 D。

## 3. 三个条件与证据量梯度

| 条件 | 输入 | 作用 |
|---|---|---|
| **只有 DNA** | 序列（v2.0 现有解码） | 基线；即现稿的方法 |
| **oracle 端点** | 序列 + 真值转录本的真实起点和终点 | 上限：端点完全已知时，序列先验能把多少区域变成正确的转录单位 |
| **真实稀疏证据** | 序列 + WTC11 ssCAGE 峰 + QuantSeq polyA 位点 | 实际场景 |

- **证据量梯度**：真实证据按 10%、30%、100% 的量给出。
  - 优先按读段量下采样（需要可选的 ssCAGE 单碱基文件）；否则按峰随机抽取。
  - 每档 3 个随机种子。
- **证据怎样进入我们的模型**（开发内容，只在 chr18 上调）：
  - G1B 语法本来就有基因进入 / 退出的边界势能（`BoundaryCoef`）；
  - 在证据位置给对应链的进入 / 退出边界加一个分数（随证据强度增加），再按现有的 MEA 解码。
  - 不改骨干和头，不需要重训。

## 4. 对照（两种信息预算）

| 预算 | 对照 | 说明 |
|---|---|---|
| 只给端点（与「真实稀疏证据」同等） | **吸附基线**：只有 DNA 的预测，把两端吸附到最近的证据峰 | DECISION 指定，门槛要求胜过它 |
| 同上 | **只用证据配对**：ssCAGE 峰与下游同链最近的 polyA 位点配对成区间（不用序列模型） | 衡量「序列先验」本身有没有贡献 |
| 同上 | AUGUSTUS（hints 模式） | 只预测编码基因、对 lncRNA 是否适用待查；不适用则写明并去掉 |
| 给完整转录组 | StringTie（长读长模式）、IsoQuant，输入另一个 PacBio 重复的比对 | 参照上限：有长读长时的现成工具。我们的用武之地是读段覆盖不到的 lncRNA，所以按表达分层报告 |

## 5. 真值（下载后细化，冻结前定死）

- **验证真值**：PacBio 转录本（ENCODE TALON GTF）中的 lncRNA。
  - 已知基因按 GENCODE V29 的 biotype；新基因按「不与同链编码基因重叠、长度 ≥ 200」归为 lnc 候选。
  - 细节要看 GTF 实际内容再定。
- **重复的分工**（建议）：
  - 一个重复作「完整转录组」对照的输入；
  - 另外两个重复都观察到的转录本作验证真值。
  - 这样对照工具不会用到真值所在的读段。
- **评分**：与第 1 周相同，S50（一对一跨度 reciprocal overlap ≥ 0.5）为主，另报 L1 和精度。
- **注意**：只有 DNA 的条件不知道细胞系，它预测出的、但 WTC11 没表达的 lncRNA 会算成假阳性。所以「只有 DNA」的精度会被低估；这本身就是「依观测而定」的论点，结果里要写明。

## 6. 区域与可验证数量

- **开发**：chr18（v2.0 的开发染色体，特征缓存已在 ont 上）。所有权重、阈值、证据分数只在这里调。
- **测试**：chr12，冻结后一次性读取。
- **chr12 上的训练窗口**：v2.0 有 151 个（61 个以 lnc 为中心、38 个编码、52 个随机），每个 24,576 bp，共约 3.7 Mb（2.8%）。两种处理方式：

| 方案 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **严格（建议）** | 像 v2.0 替换 chr9 窗口那样，替换 chr12 的 151 个窗口，重训 3 个 seed | 新窗口特征提取几分钟；训练每个 seed 约 2.4 GPU 小时，共约 8–12 GPU 小时（M1 上限 50） | ont 与 TE 共用 GPU，TE 优先，墙钟时间可能 1–2 天 |
| 低成本 | 不重训，只评估离任何训练窗口足够远的基因 | 0 | 被排除的基因偏向 lnc（61 个窗口以 lnc 为中心），测试集不再代表全部 lnc |

- **可验证数量检查**（下载后、冻结前，只看真值，不看任何预测）：chr12 上 WTC11 验证真值中的 lnc 基因数 ≥ 150，才用 chr12。否则冻结前另选染色体，选择规则也只看真值数量。
- chr12 的特征缓存约 180 GB，需像长颈鹿一样分段提取、读取、删除。

## 7. 判读（门槛来自 DECISION，冻结时只补置信区间的写法）

- **第一阶段门槛（真实稀疏证据，100% 证据量）**：
  - S50 召回 ≥ 0.30 且精度 ≥ 0.40；
  - 并且在同等证据下优于吸附基线（配对，CI 下限 > 0）。
- **必须同时报告**：
  - 有证据的 lncRNA 占全部验证真值 lncRNA 的比例；
  - 「只靠证据驱动的工具拿不到、而序列先验 + 稀疏证据能拿到」的 lncRNA 有多少（DECISION 第 2 节「方向 2 的额外风险」）。
- 结构（L2 ≥ 0.10–0.15）放到下一阶段，这里只描述。
