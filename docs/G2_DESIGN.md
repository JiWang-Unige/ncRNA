# G2 设计文档：稀疏事件半马尔可夫语法（编码 ⊗ lncRNA）

> 2026-10-21。用途：如果 P1-S2 的判定规则 1 触发（结构化解码不如无约束解码），或 G1 + S3 在正式特征上仍然碎片化，就转入 G2。这里只是设计，不实现；进入实现前会写成协议 v1.5 再执行。

## 1. G1 的局限（来自 P1-S 的证据）

- **长度只能是几何分布**：G1 是逐碱基 HMM，外显子、内含子、基因间区的长度都只能是几何分布。信号弱时，Viterbi 会切出大量短基因（R 的预测数是真值的 8 倍）。
- **长度约束只能放在解码里**：S3 在解码阶段加最小长度，能解决碎片问题，但训练和解码不一致（训练时的语法没有长度约束）。把时长链放进训练会让状态数从 17 增加到约 280，block scan 的开销随 S³ 增长，算不动。
- **没有基因级打分**：所有分数都是逐碱基累加的，模型没有"这一整段是不是一个 lncRNA 基因"的整体证据（比如外显子数、转录本总长度、TSS 与 TES 的配对）。

## 2. G2 的形式

**一个基因 = 带类型和链的外显子链**：

```
gene = (k ∈ {m, l}, s ∈ {+, -}, TSS t0, [ (a1,b1), (a2,b2), …, (an,bn) ], TES)
    a1 = TSS，bn = TES，b_i / a_{i+1} 为供体 / 受体（满足 motif）
```

**打分**（全部可微）：
- **外显子片段分**：E(a, b) = Σ_{t∈[a,b)} φ_exon(t) + ψ_len_exon(b − a)。φ 来自与 G1 相同的 C0 头，用前缀和在 O(1) 内取任意区间。ψ 是可学习的长度分，采用分桶的 log 长度先验。
- **内含子片段分**：I(b, a') = Σ φ_intron + ψ_len_intron(a' − b) + δ_donor(b) + δ_acc(a')。
- **基因级分**：ρ_k(#exons, 成熟长度) + τ_TSS(t0) + τ_TES(TES)。这是 G1 缺少的部分。
- **基因间区分**：Σ φ_IG，按同样的方式用前缀和计算。

**候选事件**（稀疏化的关键）：
- 供体 / 受体候选：所有满足 motif 的位点里，剪接头分数 ≥ θ_s 的那些。θ_s 在训练集上取，目标是让真实剪接位点的召回 ≥ 99%。
- TSS / TES 候选：边界头（TSS / PolyA 通道）上的峰。用平滑后的峰值检测，保留真实边界 ±50 bp 召回 ≥ 95% 的阈值。这一思路与 GENATATOR 的 edge 模型类似，但这里候选只是格点，不直接成为预测。
- 每一步 a → b 的扩展上限：外显子 ≤ 20 kb，内含子 ≤ 500 kb，并且只向后考虑最近的 K 个候选（K = 64）。

**推断**：
- 在候选格上做半马尔可夫前向–后向（求和积）与 Viterbi，复杂度约为 O(#候选 × K)。
- 两条链、两种类型的基因放在同一个格上，用"基因间区"串联起来；这与 coding 项目 M28 的完整基因集求和是同构的（M28 的 `full_grammar_log_partition`），只是事件换成了上面这些候选。
- 训练目标仍然是 log Z − log Z_obs，观测掩码沿用 v1.2 的标签与 unknown 处理；M30 的部分观测逻辑可以直接移植。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 候选剪枝导致召回上限（真实事件被剪掉） | 训练时把真实事件强制加入候选（observed 格子必须可行）；评估时报告"候选召回上限" |
| CPU DP 太慢（M28 的 GPU 利用率只有 11%） | 在 GPU 上按候选批量做 logsumexp；先在 1 Mb 区段上测吞吐量，再决定是否改用 Triton |
| 长度先验过拟合人类 | 分桶的 log 长度分只有几十个参数；跨谱系时冻结或重新校准 |
| TSS / TES 信号弱（0.4：AUPRC < 0.09） | 候选阈值只追求召回；判别交给基因级分和外显子 / 内含子分 |

## 4. 与 G1 + S3 的对照实验（如果启用）

- 相同特征（P1-S2 设定）、相同训练窗口、相同的整条 chr18 评估、主指标 AUPRC_lnc、3 个 seed。
- 额外报告：候选召回上限、DP 吞吐量（Mb / GPU-h）、L2 内含子链（G2 应在这一项上体现优势）。
- 预设判据（写入 v1.5 时再冻结）：G2 的 AUPRC_lnc ≥ G1 + S3 + 0.02，且 L2 Sn 更高、3 个 seed 同号，才替换 G1。

## 5. 工作量估计

- 实现：候选生成、格构建、GPU 前向–后向和 Viterbi、单元测试（用暴力枚举对照小格），约 2–3 天。
- 算力：在代理特征上 3 个 seed，约 6–10 个 T4 小时（Kaggle）。
