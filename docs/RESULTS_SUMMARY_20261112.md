# 研究结果总梳理（截至 2026-11-12，含全部负结果）

> 用途：给外部评审（人或模型）一页看全。每条结果后面是出处文档（均在 `docs/` 下）。
> 目标期刊：Nature 子刊级（Nat Commun / Nat Methods / Genome Res 一档）。
> 课题：只用 DNA 序列（ab initio），在动物基因组上联合注释蛋白编码基因与 lncRNA（外加小 ncRNA 的工程层），输出统一 GFF3。
> 约定：L1 = 位点（locus）层；L2 = 内含子链完全正确；L3 = 单个内含子 / 剪接位点层；「严格 Pr」= 只有命中注释 lnc 才算对（未注释的真 lnc 也算错，所以是下界）。

## 2026-11-13 更新：位点口径收紧，主线改为「端点是限速步骤」

本节优先于下文第 2、4、7 节中与之冲突的说法。稿件文本见 `docs/manuscript/DRAFT_results_ends.md`（第 7–10 节）。

| 实验 | 结论 | 出处 |
|---|---|---|
| B1 严格一对一位点评价 | chr20 lnc S50 Sn 0.064 / Pr 0.094（原 L1 0.306 / 0.422）；chr9 v2.0 0.069 / 0.108；GENATATOR 0.006，GENCODE v41 当预测 0.396。按事前规则落在最低一档：只能说「转录相关区域的检出」，不能说「lncRNA 位点发现」。原因是端点：lnc 起止偏差中位 8–10 kb / 9–21 kb，mRNA 1–2 kb | `phase1_results/RESULT_B1.md` |

| BND 端点诊断 | 后验里没有 lnc 端点信号（起点 1 kb 内：lnc 23%，mRNA 70%）；接缝、解码器、真值端点不可靠都已排除 | `phase1_results/RESULT_BND.md` |

**新主线**：只用序列，模型能检出与 lncRNA 相关的转录区域（GENATATOR 的约 10 倍），但很少能界定一个基因；限速步骤是转录单位端点的定位。端点已知到 1 kb 以内时，结构可以部分恢复（真值端点 + 真值剪接 0.34，GENATATOR 区间分割 0.37）；但从序列上，起点只有 CpG 岛型启动子能定位，终点完全定位不了。

原「lnc 结构定不下来，是因为 lnc 内含子多为低使用量剪接」的主线降为次要：它描述的是端点已知之后的结构问题。

## 0. 方法一句话

- 骨干：冻结的 DNA 语言模型 GENERanno-1.2b-cds 的特征。
- 头部 + 解码：17 状态「编码 ⊗ lncRNA」HMM-CRF 语法（G1），加 TSS/TES 边界头（G1B）；未注释区按「unknown」边缘化训练，证据来自 GTEx 剪接读段（U-ev 标签）；解码用外显子级最大期望精度（MEAX）+ 时长约束。
- v2.0 在此之上加位点级置信度校准；v3.0 检验加小鼠联合训练。
- 训练：人类 3,000 个窗口（约 24.6 kb），留出 chr18（开发）、chr20 / T2T chr20（v1.9 一次性测试）、chr9（v2.0 一次性测试）。
- 全程预注册：每个实验先冻结判据再读数，测试染色体只读一次。

## 3. 核心负结果：lnc 外显子结构从序列上定不下来

| 结论 | 数字 | 出处 |
|---|---|---|
| 端到端 lnc 内含子链完全正确率为 0 | chr20、chr9、T2T、所有物种、所有 seed，L2 = 0；lnc 连接精度 0.4–1.5% | `RESULT_P15.md`、`RESULT_V20_CHR9.md`、`RESULT_P16.md` |
| 接入 SpliceAI 剪接势能无效 | w0.5：L3 Sn 0.002→0.055，L2 ≤0.012；加大权重则精度掉 | `RESULT_SPLICE_DIAG.md` |

## 4. 机制分析：为什么「在哪里」可解而「怎么剪接」不可解

| 结论 | 数字 | 出处 |
|---|---|---|
| 瓶颈是剪接位点，不是基因边界（S1b，chr18；chr9 复现） | 只给真值边界 L2 0.003；只给真值剪接位点 0.168；都给 0.341（chr9：0.001 / 0.195 / 0.314） | `RESULT_S1B.md`、`RESULT_V20_CHR9.md` |
| 使用量匹配后，lnc 与 mRNA 剪接位点一样可预测（S1 / S1R；4 条染色体，4 个模型） | 匹配后 \|ΔAUROC\| ≤ 0.02，方向随染色体变；使用量效应大 10 倍（低层→高层 +0.07 至 +0.21） | `RESULT_S1.md`、`RESULT_S1R.md` |
| 注释的 lnc 内含子使用量低 16–28 倍 | GTEx 读段中位 352 对 9,194 | 同上 |
| AlphaGenome（最强剪接模型，样本内）也一样 | lnc AUROC 0.95–0.97，匹配差 ≤0.011；但 lnc 位点 AP 0.13–0.24 对 mRNA 0.82–0.84 | `RESULT_S2_AG.md` |
| 给了真值剪接位点后，结构恢复率随使用量上升 | 6% → 21% | `RESULT_S1R.md` |
| 模型靠什么找到 lnc 位点（S3，chr18 / chr20 / chr9 一致） | 启动子 CpG（+0.35）与基因跨度（+0.55 至 +0.70）；CAGE、重复比例不独立相关；反义 lnc 更难（事后） | `RESULT_S3.md` |
| TE 来源的 lnc | 外显子 TE 比例不妨碍检出；TSS 落在 TE 内的 lnc 更难（−0.064 / −0.067），事后看主要因为缺 CpG 岛启动子 | `RESULT_S3_TE.md` |

**当前主线表述**：DNA 序列能告诉我们 lncRNA 基因在哪里（靠像基因的启动子与长转录单元，人类两条留出染色体与小鼠零样本都成立），却定不了它的外显子–内含子结构；原因不是 lnc 的剪接信号特殊，而是注释的 lnc 内含子多为低使用量的剪接事件，而低使用量位点对所有现有序列模型（SpliceAI、Pangolin、自训、AlphaGenome）都难。

## 6. 已知薄弱点（自评）

1. **seed 方差大**：chr20 三个 seed Sn 0.303 / 0.402 / 0.214；val NLL 与任务指标反相关；v3.0 有 run 发散。
2. **mRNA 结构远弱于 Tiberius**（L2 0.05–0.26 对 0.557），「联合注释」的说法在编码侧不成立，目前只能说 mRNA 位点层可用。
3. **严格 Pr 只有 0.42–0.50**，对「未注释真 lnc」的独立精度证据只有一种（转录证据 59% 对 29%）。
4. **没有全基因组输出**，没有可安装的软件发布；论文图一张都没画。
5. **机制结论全是相关分析**：S3 没做计算机内突变；「低使用量导致不可预测」未做因果方向的检验。
6. **远缘物种**（果蝇、线虫）严格 Pr 极低，线虫的 lnc 预测大多落在编码基因上。
7. v3.0 之后没有新的正向方法结果；「加数据 / 加物种」这条路目前是负的。

## 7. 现阶段设想的论文骨架

1. 现有注释器看不见 lncRNA（基准）；
2. 结构化语法解码从序列端到端找到 lnc 位点（chr20、chr9、小鼠、零样本物种；转录证据验证；校准置信度）；
3. 但结构定不下来——跨模型、按使用量匹配的剪接可预测性上限，边界 / 剪接分解；
4. 位点靠什么被找到（CpG 启动子 + 长转录单元；TE-TSS 盲区）；
5. 含义：lnc 注释应当是「序列定位点、少量转录证据定结构」。
