## 结论：P0b 正式通过（限定范围），批准写 P0c 计划

**通过的口径**：在测试过的无噪声、有限候选模型下，实现正确性已确立；生物学有效性、可扩展性、实际用途都未检验。不再扩大人工图测试，不再做一轮 fix。

**它确认的**：
- F1、F3、F4、F6 是关键改进。
- oracle 独立性对当前阶段足够：路径枚举、观测相容性、观测池、支持集可行性、覆盖最优、信息受限、见证检查都是独立实现。但两者实现的是同一套数学语义，模型本身错了两边会一起错，这要靠 P0c、P1 检验。

**它指出的问题**（我核过，都成立）：
1. **presolve 复核**：
   - 方向对，但计数要拆成三项：误报（复核得到可行见证）、复核未解决、复核确认不可行。
   - 两次 HiGHS 都判不可行只能叫「求解器核验」，不能叫形式化证明。
   - oracle 的 `_lp` 把所有非成功状态都当不可行，应区分 INFEASIBLE 和 UNRESOLVED。
   - 那 5 个异常实例要存成永久回归测试，并记下 SciPy / HiGHS 版本。
2. **见证检查只在测试里做**：正式求解接口（`Model.solve`、`info_limited`）返回前也要直接检查见证。
3. **90 次跳过的报告口径与代码不符**。代码是先做结构可解检查，所以跳过的不可能是结构可解。
   - 已补算：73 次判信息受限，都有可复核的见证；17 次判可定量区分（全是 pe），没有独立证明。
   - 全部在 3 个 12 路径实例、δ = 1。报告已更正。
4. **「48% 需要全长」说过头**：统计的是返回的方案「包含」全长分子，不是「必须」。要拆三类：全长非必要、全长有代价优势、全长逻辑必要；同时报告所需连接观测的最小物理跨度。
5. **读段对的效果可能是人工图造成的**：随机图只有 4–7 个节点，一个读段对就能盖住接近整条转录本。P0c 要用真实长度和片段长度分布区分两种解释。
6. 其他小漏洞：
   - 空候选的零维 MILP；
   - 含 / 不含目标两次求解都不可行时应判 UNRESOLVED，而不是 NECESSARY；
   - 路径枚举要剪掉到不了汇点的节点，并加位点级总时间预算；
   - 代价应显式传入；
   - 丰度上下界需要 MILP 或「枚举支持集 + LP」；
   - 内含子链等价类未实现；
   - 开放端点的路径不应能获得 full 证据；
   - 读段对应允许重叠、按碱基计。

**P0c 前要先定的六个选择**：
1. **主分析粒度**：内含子链为主（因此 P0c 前必须实现等价类判定：是否存在一个可行解，使该链的所有路径同时缺席）；可信端点限定的完整转录本为次要；开放端点不作精确判定；单外显子单列。
2. **图固定与否**：主分析只用发现集建图后固定；增量 / 验证集里图外的结构记为 out-of-graph，不丢弃；另做图扩展的安全性审计。
3. **定量约束**：主分析只用质控后的结构硬约束；同文库定量作次要；跨协议定量留到 P1。
4. **δ**：不以 δ = 0 为默认；无简约约束为最保守，δ = 1 可作主要简约辅助，δ = 0 和 2 作说明与敏感性。分开报告「不依赖简约」和「依赖简约」的新增结构；优势全来自 δ = 0 不算通过。
5. **算法能选什么**：不能要求增量集返回指定读段。按 D 20% 冻结优先级，A 40% 在被选位点中随机取分子（理想化靶向采样），V 40% 评价。不能宣称实际 capture 或成本优势。
6. **主要指标与基线**：同等新增分子预算下，被 V 独立支持的新增结构数相对最强基线的增益，同时报告绝对增益。
   - 基线：随机、按丰度、按复杂度、单反例最短区分、最大分支间距、最易获得观测、直接全长支持。
   - 两个消融：全局诊断不计出现概率；计出现概率但只用单反例。

**P0c 门槛**：
- ≥ 100 个合格歧义位点，≥ 80% 算完；
- ≥ 20% 的位点在真实长度约束下存在非全长充分方案；
- 新增独立支持结构比最强基线多 ≥ 20%，配对 95% CI 下限 > 0；
- 冲突结构不明显增加；优势不能全来自 δ = 0；
- 报告图外、不可行、超时的比例。

开发集先查规模和功效再冻结。

**停止条件**：
- 考虑真实片段长度后，非全长诊断几乎消失；
- CEGIS 与单反例规则收益相当；
- 优势能被丰度或出现概率完全解释；
- 只增加模型内部的 NECESSARY，不增加独立支持的结构；
- 优势只来自事后挑选分子的 oracle 策略。

**录用概率**：维持不变（当前功能约 20%；过 P0c 约 35%；再加 SIRV 与独立协议约 50%）。工程信心提高，原创性评价不变。它的原话要点是：现在最大风险已不是算法写错，而是算法正确却不比简单规则更有用。
