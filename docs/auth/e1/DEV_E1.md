# AUTH-E1 开发：训练染色体（2026-11-24）

> 计划：`PLAN_E1.md`（作者 2026-11-24 批准）。只用 14 条训练染色体；测试染色体上没有生成任何 E1 标签。
> 代码：`scripts/auth/e1_labels.py`、`e1_dev.py`。输出：`DEV/`（`FEASIBILITY.json`、`DEV_E1.json`、`MODEL_E1.json`、日志）。ont CPU，nice 19。

## 1. rep1 读段来源核对：通过

- ENCODE 长读长流程，minimap2 `-ax splice -uf --secondary=no`。
- PacBio CCS 读段，比对方向即转录方向，只有主比对，共 2,505,856 条。
- 带 TALON 内部引物标记（`fA`）。
- 不是 CapTrap 文库，5′ 端可能偏短（计划第 2 节已写明）。

## 2. 可行性门槛：通过

合格起点组的条件：至少 1 个终点有 ≥ 2 条读段连接，至少 1 个竞争终点，起点附近 ≥ 10 条读段。

按 312 : 842 换算，测试集约 255 组，远超门槛 162（训练）/ 60（测试）。每组平均 12.1 个候选终点，其中 2.9 个有读段支持（随机选中有支持终点的概率 0.28）。

## 3. 结果（LOCO，留一染色体）

| 方法 | Top-1 | MRR |
|---|---|---|
| 随机 | 0.280 | — |
| E0 距离规则（K = 3，即 R0 的「最近 3 个取最远」） | 0.323 | — |
| E1 只用长度和距离排名 | 0.202 | 0.425 |
| **E2 终点信号、长度、跨度内证据密度** | **0.917** | 0.945 |
| E3 冻结的 AUTH 模型 | 0.824 | 0.872 |
| E4 18 个特征的组内排序模型 | 0.906 | 0.939 |

- 最强基线：**E2**（按计划在 E0–E2 中取 LOCO 最高者）。
- 区块自助预览（只作参考）：
  - E3 − E2：−0.093 [−0.151, −0.049]；
  - E4 − E2：−0.012 [−0.028, 0.000]。

**E2、E4 的主力是什么**（标准化系数）：终点 QuantSeq 信号 +3.07（E4 中 +2.95），远大于其他特征；其次是支持重复数 +0.60、长度 −0.30。

## 4. 怎么读

1. **同一个起点内选终点，几乎完全由终点自身的强度决定**：选 QuantSeq 信号最强的终点，92% 的情况下就是长读长分子实际连接的终点。
2. **冻结的 AUTH 模型在这里不如这个简单基线**（0.824 对 0.917）：它是为「区域有没有转录」训练的，看重跨度内的证据；放到同一起点内比较，这些特征反而带偏。
3. **组内专门训练的模型（E4）也没有超过 E2**：18 个特征里，除终点信号外，几乎没有额外的配对信息。
4. **长度、距离反而是负信号**（E1 低于随机）：长的配对更少得到全长读段支持。这既可能是生物学（更短的异构体更常见），也可能是 PacBio cDNA 偏向短分子、5′ 端偏短。真值本身带有这种偏向，所有方法相同。
5. 预示的结论：现有证据里的「配对信息」基本就是「哪个终点最强」。AUTH 学到的区域筛选能力，没有转化为额外的配对能力。这正是 ChatGPT 担心的情况。

## 5. 冻结前必须让作者知道的事

- **「继续」门槛在训练集上几乎不可能达到**：最强基线 E2 已经是 0.917，留给 E3 / E4 的空间只有 0.083，而「继续」要求高出 ≥ 0.10。所以测试结果实际上只可能是「停止」或「证据不足」。这是计划写门槛时没预料到的，但它本身就是信息：配对问题在现有证据下，被一条简单规则基本解决了，剩下的空间很小。
- **不建议冻结前改门槛**：改了就是看过开发结果后调门槛。建议按原计划冻结、读一次，如实报告。
